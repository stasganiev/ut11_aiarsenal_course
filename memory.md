# Память проекта

## Текущее состояние

Ветка: `develop`. Курс по AI-инструментам для 1С-разработки, конфигурация УТ 11.5.

## Решения

### 2026-08-13 — MCP-доступ в живую базу 1С

Подключены два MCP-сервера (конфиг: `.mcp.json`, scope = project):

- **`onec-data`** — [aprovodka](https://github.com/theYahia/1c-rest-mcp), npm `@theyahia/aprovodka` v4.3.0, MIT.
  Доступ по OData 3.0, 34 инструмента. Расширение конфигурации не требуется.
- **`onec-toolkit`** — [1c-mcp-toolkit](https://github.com/ROCTUP/1c-mcp-toolkit) v1.8.0, GPL-3.0.
  Внешняя обработка `MCP_Toolkit.epf` со встроенным HTTP-сервером на порту 6003.
  Даёт язык запросов 1С, метаданные, журнал регистрации.

**Почему два:** OData не умеет произвольный язык запросов 1С и не даёт метаданные модулей;
toolkit это закрывает. Обратно — toolkit требует запущенной обработки в 1С, aprovodka нет.

**Ограничения, принятые сознательно:**
- Цель — **тестовая/учебная** база, не продуктив.
- `ONEC_WRITE_MODE=off` (только чтение) по умолчанию.
- Реквизиты подключения — только в переменных окружения, в репозиторий не попадают.
- `.epf` (1.8 МБ) исключён из git через `.gitignore`, качается по инструкции.
- `execute_code` в toolkit исполняет произвольный код в базе — на продуктив не ставить.

Инструкция по настройке: `work/task_mcp_1c/setup.md`.

**2026-08-13, обновление — `onec-toolkit` запущен и проверен:**
- 1С открыта через `work/task_mcp_1c/start-mcp-toolkit.ps1` с обработкой `MCP_Toolkit.epf`,
  в форме включён «Встроенный сервер», задан токен доступа.
- Сервер `1C MCP Toolkit (Native)` v1.0.0 отвечает на `http://127.0.0.1:6003/mcp`
  (проверено `test-connection.ps1`, `initialize` → HTTP 200).
- Токен передаётся через заголовок `Authorization: Bearer`. Он хранится в переменной
  окружения `ONEC_TOOLKIT_TOKEN` (User scope), в `.mcp.json` добавлен `--header
  "Authorization: Bearer ${ONEC_TOOLKIT_TOKEN}"` в блок `onec-toolkit`.
- Важно: обработка должна оставаться открытой в 1С — закрыли сеанс, сервер погас.
- Требуется перезапуск Claude Code после смены переменных окружения / `.mcp.json`,
  чтобы MCP-клиент переподключился и подтянул инструменты toolkit.

**2026-08-14 — `onec-data` (OData): публикация настроена и проверена.**

На машине изначально был только клиентский дистрибутив 1С (нет `webinst.exe`, нет IIS).
Путь до рабочей публикации:
1. Установлен компонент Windows **IIS** (`Enable-WindowsOptionalFeature`, вручную от админа) —
   роль веб-сервера отсутствовала на машине.
2. Из полного дистрибутива `C:\temp\Install\windows64full_8_3_27_2074\setup.exe` довустановлен
   компонент платформы **«Модули расширения веб-сервера»** — появился `webinst.exe`,
   `wsisapi.dll` в `bin\` версии 8.3.27.2074.
3. Публикация: `webinst -publish -iis -wsdir ut11_odata -dir "C:\inetpub\wwwroot\ut11_odata"
   -connstr "File=""C:\dev\bases1c\ut11aiarsenal_course"";"` — успешно, виртуальный каталог
   `/ut11_odata` зарегистрирован в IIS Default Web Site.
4. В сгенерированном `default.vrd` `standardOdata` по умолчанию `enable="false"` — включили
   вручную (`enable="true"`), правка файла требует прав администратора на `C:\inetpub`.
5. В этой сборке БСП 3.1 пункт меню «Стандартный интерфейс OData» **не выведен в интерфейс
   Администрирования** (не найден ни в «Общие настройки», ни в «Интернет-поддержка и сервисы»).
   Доступен только как обработка `Обработка.НастройкаСтандартногоИнтерфейсаOData` — открывается
   напрямую по имени (`e1cib/app/Обработка.НастройкаСтандартногоИнтерфейсаOData`) или через
   «Все функции». Есть также константа `ПользовательСтандартногоИнтерфейсаOData` (была `null`)
   и роль `УдаленныйДоступOData`.
6. Пользователь `admin` / пароль `123` — добавлен как пользователь стандартного интерфейса
   OData через ту обработку. **Пароль открытый, только для локальной учебной базы.**
7. Проверка: `GET $metadata` под Basic Auth (`admin:123`) → HTTP 200, ~1353 `EntitySet`
   (весь состав, не только узкий список из `setup.md` — так решили осознанно на этот раз).
   Подтверждено наличие нужных: `Catalog_Номенклатура/Партнеры/Контрагенты/Организации/
   Склады/СоглашенияСКлиентами/Акции/ВидыЦен/ДоговорыКонтрагентов`,
   `Document_ЗаказКлиента/РеализацияТоваровУслуг`, `InformationRegister_ЦеныНоменклатуры`,
   `AccumulationRegister_Закупки`.
   **Отсутствует** в составе: `InformationRegister_СоглашенияОЦенообразовании` (кастомный
   регистр проекта, не был отмечен при настройке) — если понадобится читать
   МинимальнаяЦена/ПравилоОкругления через OData, его нужно доотметить в той же обработке.

Конфиг `.mcp.json`: сервер `onec-data`, команда `npx -y @theyahia/aprovodka`, реквизиты
через `env` → переменные окружения `ONEC_BASE_URL`, `ONEC_LOGIN`, `ONEC_PASSWORD`
(User scope, не в репозитории), `ONEC_WRITE_MODE=off`. Smoke-test пройден:
`aprovodka` стартует, регистрирует 34 инструмента.

**2026-08-14, вторая половина дня — найдена и исправлена причина 404 на всех запросах:**
`ONEC_BASE_URL` был изначально задан с уже готовым OData-путём
(`http://localhost/ut11_odata/odata/standard.odata`), а клиент `aprovodka` сам дописывает
суффикс `/odata/standard.odata` к переданному URL — получался двойной путь
`.../odata/standard.odata/odata/standard.odata/...` → 404 на любом инструменте, кроме
офлайн `get_config_preset`. Правильное значение — **адрес публикации без суффикса**:
`ONEC_BASE_URL=http://localhost/ut11_odata`. Диагностировано через `claude --debug` —
полезный приём при похожих проблемах с MCP-серверами в будущем.

После исправления и перезапуска Claude Code проверено вживую: `get_by_key` вернул реальную
карточку контрагента «ООО "1С-СОФТ"» (ИНН 7730643014), `count_entities` — 47 документов
`Document_РеализацияТоваровУслуг`, `get_catalogs` по `Catalog_Номенклатура` — реальные позиции
номенклатуры. `onec-data` подтверждённо рабочий, доступ к живой базе есть.

**Отдельная находка (важно для задачи TT по ценообразованию):** модуль
`ЦенообразованиеРасчет` обращается к `Соглашение.МинимальнаяЦена` и
`Соглашение.ПравилоОкругления` как к реквизитам справочника `СоглашенияСКлиентами` —
таких реквизитов там нет, это ресурсы регистра `СоглашенияОЦенообразовании`.
Подтверждено эмпирически через `execute_code`: `РассчитатьЦену` падает с исключением
"Object field not found (МинимальнаяЦена)" на первом же обращении, для любых входных
данных. Также `Справочники.ВидыЦен.Основная` — обращение к несуществующему предопределённому
элементу (у `ВидыЦен` в этой базе вообще нет предопределённых элементов). Оба — блокеры
уровня «функция не работает вообще», приоритетнее всех 13 сценариев из
`work/tests/edge/test_escapes.md`. Требуют правки кода, не данных.

**Известное ограничение `onec-toolkit`:** `execute_code` жёстко блокирует любой текст,
содержащий подстроку `Записать` — то есть запись объектов (`Записать()`) через toolkit
невозможна в принципе, это осознанная защита самого инструмента. Наполнение тестовыми
данными нужно делать либо вручную в 1С, либо через `onec-data` (`create_catalog_item` /
`create_document` — но `ONEC_WRITE_MODE=off` сейчас тоже блокирует запись, это отдельный,
independent от toolkit механизм защиты).
