## Gitflow

### Стандарт коммитов

В конце слыслового блока или всей задачи сразу предлагай один вариант текста комментария для коммита по этим правилам

### Формат

```
<НомерЗадачи> <Type> (scope): Краткое описание
```

### Типы (Type)

- feat(scope): - новая функциональность
- fix(scope): - исправление ошибок
- docs(scope): - изменения в документации (комментарии, описания, README)
- style(scope): - форматированин кода
- refactor(scope): - улучшение кода без изменения поведения (рефакторинг)
- struct(scope): - логирование, мониторинг, настройки
- test(scope): - добавление тестов
- chore(scope): - рутинные задачи (обновление зависимостей и т.д.)

`scope` - короткое имя подсистемы на английском (`pricing`, `sales`, `reports`).
Описание после двоеточия - на русском, в повелительном наклонении.

### Пример

```bash
git commit -m "TT-007 feat: Учет категории клиента при расчете скидки"
```
