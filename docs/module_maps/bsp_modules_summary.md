# Краткая шпаргалка по основным модулям БСП 3.1.x

**Назначение файла:** база знаний для Custom GPT «БСП-аудитор для 1С». Даёт ассистенту достоверный перечень модулей и экспортных методов БСП, чтобы он опирался не только на «общую эрудицию», но и на проверенный контекст. Сгруппировано под три категории аудита: «велосипед» / «частичное использование» / «неоптимально в цикле».

**Версия БСП:** 3.1.10.
**Платформа:** 1С:Предприятие 8.3.27.
**Важно для ассистента:** перечень не исчерпывающий. Если метода нет в этом файле — не выдумывай сигнатуру, пиши «уточнить по документации БСП конкретной версии».

---

## Как пользоваться этим файлом (для ассистента)

1. Сначала классифицируй фрагмент кода по трём категориям.
2. Найди подходящий модуль БСП в таблицах ниже.
3. Сверь имя метода и контекст вызова (Сервер / Клиент / КлиентСервер).
4. Если точного метода нет в списке — не выдумывай, пометь «уточнить по документации».

## 1. ОбщегоНазначения (серверный)

Самый частый источник находок по категориям 2 и 3.

| Метод | Назначение | Категория аудита |
|-------|-----------|------------------|
| `ЗначениеРеквизитаОбъекта(Ссылка, ИмяРеквизита)` | Один реквизит одного объекта = один запрос | Часто используется правильно, но в цикле → категория 3 |
| `ЗначенияРеквизитаОбъекта(Ссылка, ИменаРеквизитов)` | Несколько реквизитов ОДНОГО объекта за один запрос | Замена нескольких `ЗначениеРеквизитаОбъекта` по одному объекту |
| `ЗначенияРеквизитовОбъектов(Ссылки, ИменаРеквизитов)` | Реквизиты МНОЖЕСТВА объектов за один запрос → `Соответствие[Ссылка → Структура]` | **Главный пакетный метод против цикла (категория 3)** |
| `УстановитьБезопасныйРежим(...)` | Управление безопасным режимом | Велосипед при ручной работе с привилегиями |
| `ВыполнитьВКонтекстеИмениПользователя(...)` | Выполнение в контексте пользователя | — |
| `ТекущаяДатаСеанса()` | Дата сеанса вместо `ТекущаяДата()` на клиенте | Велосипед при ручном получении серверного времени |

**Ключевое правило для категории 3:** любой вызов `ЗначениеРеквизитаОбъекта` внутри `Для Каждого ... Цикл` — кандидат на замену пакетным `ЗначенияРеквизитовОбъектов`. Эффект: `O(N)` запросов → `O(1)`.

## 3. ФайловаяСистема (серверный) + РаботаСФайламиКлиентСервер (клиент-серверный)

Главный источник находок по категории 1 («велосипед» на временных файлах).

| Метод | Модуль | Назначение | Заменяет самописное |
|-------|--------|-----------|---------------------|
| `СоздатьВременныйКаталог(Расширение)` | ФайловаяСистема | Атомарное создание временного каталога, авто-удаление при завершении сеанса | `КаталогВременныхФайлов()` + `СоздатьКаталог()` + ручной `Попытка` |
| `УдалитьВременныйКаталог(Путь)` | ФайловаяСистема | Безопасное удаление с обходом подкаталогов и логированием | Ручной `НайтиФайлы` + `УдалитьФайлы` в цикле |
| `УникальноеИмяФайла(Имя)` | ФайловаяСистема | Гарантированно уникальное имя в пределах сеанса | Конкатенация даты + GUID вручную |
| `РасширениеИмениФайла(ИмяФайла)` | РаботаСФайламиКлиентСервер | Расширение из имени файла | Ручной `СтрНайти` + `Сред` |
| `ИмяФайлаБезРасширения(ИмяФайла)` | РаботаСФайламиКлиентСервер | Имя без расширения | Ручной разбор строки |
| `ПолноеИмяФайла(Каталог, Имя)` | РаботаСФайламиКлиентСервер | Корректная склейка пути с разделителями | Ручная конкатенация с `\` |

**Риск миграции (важно для ассистента):** `ФайловаяСистема.*` — серверный модуль, проверять контекст вызова. `УникальноеИмяФайла` уникален в пределах одного сеанса — при распределённом сохранении учитывать отдельно.

## 4. Пользователи (серверный) + ПользователиКлиент / ПользователиСлужебный

Главный источник находок по категории 2 («частичное использование»).

| Метод | Модуль | Назначение | Заменяет самописное |
|-------|--------|-----------|---------------------|
| `ТекущийПользователь()` | Пользователи | Ссылка на текущего пользователя ИБ | Ручной поиск в справочнике |
| `ИмяТекущегоПользователя()` | Пользователи | Строка имени для журнала | Запрос за реквизитом «Наименование» |
| `ЭтоВнешнийПользователь(Пользователь)` | Пользователи | Проверка типа без сравнения `Тип(...)` | Ручное `Тип(...) = Тип("СправочникСсылка.ВнешниеПользователи")` |
| `ЭтоПолноправныйПользователь(Пользователь, ...)` | Пользователи | Проверка наличия роли «ПолныеПрава» | Ручной запрос к РС `СоставыГрупп` / `РолиГрупп` |
| `НастройкиТекущегоПользователя()` | ПользователиСлужебный | Служебные настройки пользователя | Ручное хранение в своём регистре |

**Правило для категории 2:** если в коде есть `Пользователи.ТекущийПользователь()`, но проверки роли/типа сделаны вручную — это «соседние» методы той же подсистемы, которые недоиспользованы.

## 5. УправлениеДоступом (серверный) — если подсистема подключена

| Метод | Назначение |
|-------|-----------|
| `ЕстьРоль(ИмяРоли, Пользователь)` | Проверка произвольной роли (если подсистема подключена) |
| `ПравоДоступа(Право, ОбъектМетаданных, Пользователь)` | Платформенная проверка права (доступна и без подсистемы) |

**Важно для ассистента:** `УправлениеДоступом` — опциональная подсистема. Если пользователь сообщил, что она ИСКЛЮЧЕНА — не предлагать `ЕстьРоль`, использовать платформенный `ПравоДоступа` или `Пользователи.ЭтоПолноправныйПользователь`.

---

## 6. ХранилищеСистемныхНастроек (платформа, но БСП оборачивает паттерны)

| Метод | Назначение | Заменяет самописное |
|-------|-----------|---------------------|
| `Сохранить(Ключ, Настройки, ...)` | Сохранение пользовательских настроек | Свой регистр сведений под настройки UI |
| `Загрузить(Ключ, ...)` | Загрузка по тем же ключам | Ручной запрос к своему регистру |

**Правило для категории 1/2:** хранение настроек интерфейса пользователя через свой регистр — «велосипед». Если используется только `Сохранить`, но загрузка вручную — категория 2.

## 7. Прочие частотные модули (краткий ориентир)

| Модуль | Когда искать «велосипед» |
|--------|--------------------------|
| `ОтправкаSMSИEmail` | Ручная отправка email через `WSCсылку` / `ИнтернетПочта` напрямую |
| `РегламентныеЗаданияСервер` | Регламентные задания, написанные «с нуля» без обёрток БСП |
| `УправлениеПечатью` | Печатные формы через макеты вручную |
| `ЗагрузкаВыгрузкаДанных` | Ручная сериализация в XML/JSON для обмена |
| `РаботаСДатами` (`ОбщегоНазначенияКлиентСервер`) | Ручные расчёты начала/конца периода |

## Сводное правило трёх вопросов (главный месседж воркшопа)

Ассистент проверяет код по трём вопросам:

1. **Есть ли готовое в БСП?** → категория 1 «велосипед»
2. **Используется ли БСП на полную глубину?** → категория 2 «частичное»
3. **Используется ли БСП эффективно?** → категория 3 «неоптимально в цикле»

Эти три вопроса исчерпывают методологию «оптимизации под БСП».
