# MCP-серверы для прямого доступа в живую базу 1С

Дата: 2026-08-13
Целевая база: **тестовая/учебная** УТ 11.5 (не продуктив)

## Что установлено

Установлено два сервера — они закрывают разные задачи и дополняют друг друга.

| Сервер | Имя в конфиге | Канал доступа | Чем силён |
|---|---|---|---|
| [aprovodka](https://github.com/theYahia/1c-rest-mcp) | `onec-data` | OData 3.0 (HTTP) | Данные: справочники, документы, все регистры, виртуальные таблицы остатков/оборотов. Безопасная запись. |
| [1c-mcp-toolkit](https://github.com/ROCTUP/1c-mcp-toolkit) | `onec-toolkit` | Обработка `.epf` внутри 1С | Язык запросов 1С, метаданные, журнал регистрации, права доступа, поиск ссылок |

Конфиг: [.mcp.json](../../.mcp.json) в корне проекта (scope = project).
Файл обработки: [work/task_mcp_1c/bin/MCP_Toolkit.epf](bin/MCP_Toolkit.epf) (v1.8.0, скачан из репозитория).

Реквизиты подключения в конфиг **не зашиты** — подставляются из переменных окружения.
Поэтому `.mcp.json` безопасно коммитить.

## 1. aprovodka (`onec-data`) — доступ по OData

### 1.1. Публикация OData на стороне 1С

Требуется один раз на тестовой базе.

1. Конфигуратор -> **Администрирование -> Публикация на веб-сервере**
2. Включить флаг **«Публиковать стандартный интерфейс OData»**
3. Опубликовать, перезапустить пул приложений IIS / службу Apache

### 1.2. Состав объектов, доступных через OData

По умолчанию через OData **не отдаётся ничего** — состав задаётся явно.

В режиме 1С:Предприятие: **Администрирование -> Стандартный интерфейс OData ->
Настроить состав стандартного интерфейса OData**.

Отметить только то, что реально нужно агенту. Для курса обычно достаточно:
- `Справочник.Номенклатура`, `Справочник.Партнеры`, `Справочник.Контрагенты`
- `Справочник.Организации`, `Справочник.Склады`
- `Документ.ЗаказКлиента`, `Документ.РеализацияТоваровУслуг`
- `РегистрНакопления.ТоварыНаСкладах`
- `РегистрСведений.КурсыВалют` (по текущей задаче TT-011)

> Чем уже состав — тем меньше поверхность доступа и тем короче ответы метаданных.

### 1.3. Пользователь 1С для агента

Завести **отдельного** пользователя, не использовать свой:

- Имя: например `mcp_agent`
- Аутентификация 1С:Предприятия, пароль задан
- Флаг **«Защита от опасных действий»** — оставить включённым
- Профиль доступа — минимально необходимый, на чтение нужных объектов
- Снять флаг «Показывать в списке выбора»

### 1.4. Переменные окружения

Базовый URL строится так:

```
http://<хост>/<имя_публикации>/odata/standard.odata
```

Задать в PowerShell (постоянно, для текущего пользователя):

```powershell
[Environment]::SetEnvironmentVariable('ONEC_BASE_URL','http://localhost/ut_test/odata/standard.odata','User')
[Environment]::SetEnvironmentVariable('ONEC_LOGIN','mcp_agent','User')
[Environment]::SetEnvironmentVariable('ONEC_PASSWORD','<пароль>','User')
[Environment]::SetEnvironmentVariable('ONEC_WRITE_MODE','off','User')
```

После этого **перезапустить VS Code / Claude Code** — переменные читаются при старте процесса.

### 1.5. Режимы записи `ONEC_WRITE_MODE`

| Значение | Поведение |
|---|---|
| `off` | Только чтение. Все пишущие инструменты заблокированы. **Значение по умолчанию.** |
| `preview` | Показывает, что было бы записано, но не пишет |
| `approval` | Пишет только после явного подтверждения |

Начинаем с `off`. Повышать только осознанно и только на тестовой базе.

### 1.6. Проверка публикации до запуска агента

```powershell
$u='mcp_agent'; $p='<пароль>'
$h=@{ Authorization = 'Basic ' + [Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes("${u}:${p}")) }
Invoke-RestMethod -Uri 'http://localhost/ut_test/odata/standard.odata/$metadata' -Headers $h | Out-Null
'OData отвечает'
```

Если здесь ошибка — MCP тоже не поднимется. Разбираться на этом шаге.

## 2. 1c-mcp-toolkit (`onec-toolkit`) — доступ через обработку

### 2.1. Запуск

1. Открыть тестовую базу в режиме **1С:Предприятие**
2. **Файл -> Открыть** -> `work/task_mcp_1c/bin/MCP_Toolkit.epf`
3. В форме выбрать режим **«Встроенный сервер»**
4. Задать **токен доступа** (произвольная строка) — не оставлять пустым
5. Нажать **«Запустить сервер»**

Сервер слушает `http://127.0.0.1:6003/mcp`.

> Обработка должна оставаться открытой. Закрыли 1С — сервер погас, инструменты отвалились.

### 2.2. Токен

Токен из формы передаётся заголовком `Authorization: Bearer <токен>`.
Текущий `.mcp.json` использует `mcp-remote` без заголовка — это рабочий вариант,
когда 1С и Claude Code на одной машине и порт 6003 не открыт наружу.

Если 1С на другой машине — задать URL и не оставлять сервер без токена:

```powershell
[Environment]::SetEnvironmentVariable('ONEC_TOOLKIT_URL','http://<ip-1c>:6003/mcp','User')
```

и добавить в `.mcp.json` в блок `onec-toolkit` заголовок:

```json
"--header", "Authorization: Bearer <токен>"
```

### 2.3. Что даёт

`execute_query`, `execute_code`, `get_metadata`, `get_event_log`,
`get_object_by_link`, `get_link_of_object`, `find_references_to_object`,
`get_access_rights`, `get_bsl_syntax_help`, `get_screenshot`,
`restart_1c_session`, `close_1c_session`.

## Риски, которые надо держать в голове

1. **`execute_code` выполняет произвольный код в базе.** Это не read-only инструмент.
   Только тестовая база. На продуктив toolkit в таком виде не ставить.
2. **Обработка работает под правами открывшего её пользователя.** Открыли под полными
   правами — агент получил полные права. Открывать под ограниченным пользователем.
3. **`.epf` из интернета исполняется внутри вашей базы.** Файл зафиксирован в `work/`,
   версия v1.8.0. При обновлении — пересматривать, что изменилось.
4. **OData отдаёт данные в обход бизнес-логики форм.** Права ролей соблюдаются,
   а вот проверки на уровне форм — нет.
5. Порт 6003 не публиковать наружу.

---

## Проверка после настройки

Перезапустить Claude Code, затем:

- `/mcp` — оба сервера должны быть в статусе connected
- Проверочный запрос к `onec-data`: получить список метаданных
- Проверочный запрос к `onec-toolkit`: `get_metadata` или простой `execute_query`

Если `onec-data` не поднялся — почти всегда дело в `ONEC_BASE_URL` или в том,
что объект не отмечен в составе интерфейса OData.

## Прочие найденные варианты (не ставились)

Полный каталог: [Untru/1c-mcp](https://github.com/Untru/1c-mcp).

- **http1c / MCP-DB-Client** ([DitriXNew](https://github.com/DitriXNew/MCP-DB-Client)) — нативная DLL + расширение,
  инструменты `execute` / `query` / `evaluate`. Мощно, но требует сборки C++ (VS Build Tools, CMake, Ninja).
- **1c_mcp** ([vladimir-kharin](https://github.com/vladimir-kharin/1c_mcp)) — фреймворк: расширение конфигурации
  + Python-прокси. Логику инструментов пишете сами. Уместен, когда нужны свои доменные инструменты.
- **v8-session-manager** — агрегация нескольких клиентских сессий в один MCP-эндпоинт.
- **ARQA MCP Server** — коммерческий, закрытый.

Для анализа кода и метаданных без живой базы (bsl-analyzer, mcp-bsl-platform-context,
onec-help-mcp и др.) — см. тот же каталог, раздел исходников.
