## Когда подавать структуру, а когда полный код

| Тип задачи | Что отправлять |
|------------|---------------|
| Архитектурное решение (куда встроить, что создать) | **Только структура** |
| Описание нового объекта БД | **Только структура** |
| Контракт новой функции | **Структура + сигнатуры затронутых функций** (Приём 1) |
| Реализация одной функции | **Сигнатуры зависимостей** (Приём 1) **+ структура целевых объектов БД** |
| Рефакторинг существующей функции | **Полный код целевой функции + сигнатуры вызывающих** (нарезка по задаче из Урока 15) |
| Диагностика бага | **Минимальный стектрейс (Приём 2) + сигнатуры или код целевой функции** |

**Главное правило:** структура подходит для **«где / куда / какой контракт»**, полный код нужен только для **«как именно написать»**.

## Как сгенерировать структуру своей конфигурации

Если у тебя нет готового описания — можешь попросить AI:

```markdown
# Задача
Я пришлю тебе несколько модулей и регистров своей конфигурации.
Построй сжатую структуру в формате:
- Подсистема
- Документы (имя + ключевые реквизиты в скобках)
- Справочники
- Регистры (тип, измерения → ресурсы)
- Общие модули (имя, контекст, объём, краткое назначение)
- Перечисления
- Подключённые подсистемы БСП
- Точки расширения

Максимум 50 строк, плотный текст, без воды.

[Прикладываемые модули и описания]
```

Сгенерированную структуру сохрани рядом с кодом как `СТРУКТУРА_ПОДСИСТЕМЫ.md` — это **постоянный артефакт**, который ты будешь подавать в каждый новый диалог как первое сообщение.
