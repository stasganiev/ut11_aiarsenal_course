# Паспорт подсистемы «Ценообразование»

## Назначение

Подсистема рассчитывает итоговую цену реализации единицы номенклатуры для конкретного контрагента: определяет процент скидки на основании договора, VIP-статуса, объёма заказа и сезонных акций, при необходимости подменяет базовую цену индивидуальной ценой из соглашения и возвращает конечную цену с учётом скидки.

## Справочники

Подсистема не владеет собственными справочниками. Использует внешние:

- `Номенклатура` — объект ценообразования (позиция, для которой определяется цена).
- `Контрагенты` — покупатель; определяет VIP-статус (реквизит VIP) и индивидуальные соглашения.
- `ДоговорыКонтрагентов` — источник базовой ставки дисконтирования.

## Документы

Подсистема не содержит собственных документов. Результат расчёта применяется к документу продажи, переданному извне (через метод `ПрименитьСкидкуКДокументу`): модуль изменяет колонки `ПроцентСкидки`, `СуммаСкидки`, `Сумма` табличной части «Товары» и реквизит `СуммаДокумента`.

## Регистры

| Регистр | Тип | Что хранит |
|---|---|---|
| `ЦеныНоменклатуры` | Регистр сведений (внешний) | Базовые цены номенклатуры по видам цен на дату |
| `СоглашенияОЦенообразовании` | Регистр сведений (периодический, независимый) | Индивидуальные цены номенклатуры для конкретного контрагента. Измерения: `Номенклатура`, `Контрагент`. Ресурс: `ИндивидуальнаяЦена` (Число 15.2). |

## Общие модули

Подробные описания с сигнатурами — в файлах документации:

- [РасчётСкидок](doctech/РасчётСкидок.md) — расчёт итогового процента скидки и применение скидки к строкам документа; получение актуальной цены номенклатуры.
  - `РассчитатьСкидку(Клиент, Договор, СуммаЗаказа, ДатаЗаказа)` → Число
  - `ПрименитьСкидкуКДокументу(ДокументОбъект)`
  - `ПолучитьАктуальнуюЦену(Номенклатура, ВидЦены, ДатаАктуальности = Неопределено)` → Число

- [ЦенообразованиеСервер](doctech/ЦенообразованиеСервер.md) — оркестратор: получает итоговую цену с учётом индивидуальных условий контрагента и скидки.
  - `ПолучитьИтоговуюЦенуСоСкидкой(Номенклатура, Контрагент, СуммаЗаказа, ВидЦены, Договор, Дата)` → Число

Оба модуля — серверные, с доступом из внешнего соединения, без повторного использования возвращаемых значений.

## Функциональные опции и константы

| Объект | Тип | Значение по умолчанию | Влияние на работу |
|---|---|---|---|
| `УчитыватьИндивидуальныеЦены` | Константа `xs:boolean` | — | Хранилище значения функциональной опции |
| `УчитыватьИндивидуальныеЦены` | Функциональная опция | false | При включении `ЦенообразованиеСервер` подменяет базовую цену индивидуальной ценой из регистра `СоглашенияОЦенообразовании`; сам регистр скрывается/показывается в интерфейсе через эту опцию |
| `МаксимальнаяСкидкаПоУмолчанию` | Константа `xs:decimal` (6.2) | — | Верхняя граница итогового процента скидки; применяется в обоих модулях |

## Границы подсистемы

**Входные данные:** ссылки на `Номенклатуру`, `Контрагента`, `Договор`, вид цены, дату, сумму заказа.  
**Выходные данные:** итоговый процент скидки (Число), итоговая цена реализации (Число), изменённый объект документа продажи.  
**Не входит в подсистему:** регистр `ЦеныНоменклатуры`, справочники `Номенклатура` / `Контрагенты` / `Партнёры` / `ДоговорыКонтрагентов` — используются только для чтения.
