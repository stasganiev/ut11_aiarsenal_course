# Тесты подсистемы «Ценообразование»

---

## 1. Дымовые тесты (Smoke)

Запускаются после каждого обновления конфигурации. Падение любого теста блокирует дальнейшее тестирование.

**Подготовка:** в тестовой базе должны существовать:
- Номенклатура `НоменклатураТест` с записью в `ЦеныНоменклатуры` (ВидЦены = `Основная`, Цена = 1000 руб., дата ≤ сегодня).
- Контрагент `КонтрагентТест`, Договор `ДоговорТест` (СтавкаДисконтирования = 5%).
- Константа `МаксимальнаяСкидкаПоУмолчанию` = 30.
- Константа `УчитыватьИндивидуальныеЦены` = Ложь.

| № | Тест | Что вызываем / делаем | Ожидаемый результат | Критичность |
|---|---|---|---|---|
| S-01 | Вызов `РассчитатьСкидку` без ошибок | `РасчётСкидок.РассчитатьСкидку(КонтрагентТест, ДоговорТест, 10000, ТекущаяДата())` | Возвращает число ≥ 0 без исключения | Блокирующий |
| S-02 | Вызов `ПолучитьАктуальнуюЦену` без ошибок | `РасчётСкидок.ПолучитьАктуальнуюЦену(НоменклатураТест, «Основная»)` | Возвращает число > 0 (= 1000) без исключения | Блокирующий |
| S-03 | Вызов `ПрименитьСкидкуКДокументу` без ошибок | Создать в памяти объект документа с одной строкой ТЧ «Товары» (Цена=1000, Количество=1), вызвать `РасчётСкидок.ПрименитьСкидкуКДокументу(ДокОбъект)` | Нет исключения; `ПроцентСкидки`, `СуммаСкидки`, `Сумма` в строке заполнены числами | Блокирующий |
| S-04 | Вызов `ПолучитьИтоговуюЦенуСоСкидкой` без ошибок | `ЦенообразованиеСервер.ПолучитьИтоговуюЦенуСоСкидкой(НоменклатураТест, КонтрагентТест, 10000, «Основная», ДоговорТест, ТекущаяДата())` | Возвращает число > 0 без исключения | Блокирующий |
| S-05 | Итоговая цена не превышает базовую | Результат S-04 | Итоговая цена ≤ 1000 | Блокирующий |
| S-06 | Константа `МаксимальнаяСкидкаПоУмолчанию` читается | `Константы.МаксимальнаяСкидкаПоУмолчанию.Получить()` | Возвращает 30 (число, без исключения) | Высокий |
| S-07 | Функциональная опция `УчитыватьИндивидуальныеЦены` читается | `ПолучитьФункциональнуюОпцию("УчитыватьИндивидуальныеЦены")` | Возвращает Ложь без исключения | Высокий |
| S-08 | Регистр `СоглашенияОЦенообразовании` доступен для чтения | Открыть список регистра `СоглашенияОЦенообразовании` под ролью «МенеджерПродаж» | Форма списка открывается без ошибки прав доступа | Высокий |
| S-09 | `ПолучитьАктуальнуюЦену` с явной датой | `РасчётСкидок.ПолучитьАктуальнуюЦену(НоменклатураТест, «Основная», ТекущаяДата())` | Возвращает то же число, что и S-02 | Высокий |
| S-10 | `РассчитатьСкидку` возвращает число, не превышающее `МаксимальнаяСкидкаПоУмолчанию` | `РасчётСкидок.РассчитатьСкидку(КонтрагентТест, ДоговорТест, 10000, ТекущаяДата())` | Результат ≤ 30 | Блокирующий |
| S-11 | Менеджер продаж вызывает `ПолучитьИтоговуюЦенуСоСкидкой` без ошибки прав | Выполнить S-04 под пользователем с ролью «МенеджерПродаж» | Нет исключения о недостаточности прав | Высокий |
| S-12 | Администратор скидок управляет константой | Под ролью «АдминистраторСкидок» записать `МаксимальнаяСкидкаПоУмолчанию` = 25, прочитать обратно | Значение = 25; нет исключения о правах | Высокий |

## 2. Функциональные тесты

**Условные обозначения тестовых фикстур:**
- `МаксСкидка` — константа `МаксимальнаяСкидкаПоУмолчанию`
- `ОпцияИндЦены` — функциональная опция `УчитыватьИндивидуальныеЦены`
- `БазЦена` — 1000 руб. (запись в `ЦеныНоменклатуры`)
- `БазСтавка` — реквизит `СтавкаДисконтирования` договора
- Все тесты — изолированные: перед каждым устанавливать только описанные параметры.

| № | Тест | Категория | Входные данные | Ожидаемый результат | Критичность |
|---|---|---|---|---|---|
| F-01 | Базовая скидка по договору | Положительный | `БазСтавка` = 10%, VIP = Нет, `СуммаЗаказа` = 1000, без сезонной акции, `МаксСкидка` = 30 | `РассчитатьСкидку` → 10 | Блокирующий |
| F-02 | VIP-надбавка прибавляется к базовой ставке | Положительный | `БазСтавка` = 10%, VIP = Да (надбавка = 5%), `СуммаЗаказа` = 1000, без акции, `МаксСкидка` = 30 | `РассчитатьСкидку` → 15 | Блокирующий |
| F-03 | Бонус за крупную сумму заказа прибавляется | Положительный | `БазСтавка` = 5%, VIP = Нет, `СуммаЗаказа` = 100 000 (порог крупного заказа), `МаксСкидка` = 30 | `РассчитатьСкидку` > 5 (= 5 + бонус за объём) | Высокий |
| F-04 | Сезонная акция прибавляется к итоговому проценту | Положительный | `БазСтавка` = 5%, VIP = Нет, `СуммаЗаказа` = 1000, дата попадает в период сезонной акции, `МаксСкидка` = 30 | `РассчитатьСкидку` > 5 (= 5 + сезонная надбавка) | Высокий |
| F-05 | Скидка ограничена потолком `МаксСкидка` | Граничный | `БазСтавка` = 20%, VIP = Да (+5%), `СуммаЗаказа` = 100 000 (бонус +10%), сезонная акция (+5%), `МаксСкидка` = 25 | `РассчитатьСкидку` = 25 (не 40) | Блокирующий |
| F-06 | Нулевая ставка договора → скидка от остальных факторов | Граничный | `БазСтавка` = 0%, VIP = Нет, `СуммаЗаказа` = 1000, без акции, `МаксСкидка` = 30 | `РассчитатьСкидку` = 0 | Высокий |
| F-07 | Итоговая скидка не бывает отрицательной | Негативный | `БазСтавка` = 0%, VIP = Нет, `СуммаЗаказа` = 0, без акции | `РассчитатьСкидку` ≥ 0 (не отрицательное) | Высокий |
| F-08 | `МаксСкидка` = 0 → скидки нет никогда | Граничный | `БазСтавка` = 15%, VIP = Да, `МаксСкидка` = 0 | `РассчитатьСкидку` = 0 | Высокий |
| F-09 | `ПрименитьСкидкуКДокументу` пересчитывает строки корректно | Положительный | Документ с двумя строками: (Цена=1000, Кол=2) и (Цена=500, Кол=1); `РассчитатьСкидку` → 10% | Строка 1: `СуммаСкидки`=200, `Сумма`=1800; строка 2: `СуммаСкидки`=50, `Сумма`=450; `СуммаДокумента`=2250 | Блокирующий |
| F-10 | `ПрименитьСкидкуКДокументу` при скидке 0% не меняет суммы | Граничный | Документ с одной строкой (Цена=1000, Кол=1), скидка = 0% | `СуммаСкидки`=0, `Сумма`=1000, `СуммаДокумента`=1000 | Средний |
| F-11 | `ОпцияИндЦены` = Ложь → базовая цена из `ЦеныНоменклатуры` | Положительный | `ОпцияИндЦены` = Ложь; `БазЦена` = 1000; в `СоглашенияОЦенообразовании` есть запись с ИндЦена = 700 | `ПолучитьИтоговуюЦенуСоСкидкой` использует 1000 как базу (не 700) | Блокирующий |
| F-12 | `ОпцияИндЦены` = Истина → индивидуальная цена подменяет базовую | Положительный | `ОпцияИндЦены` = Истина; `БазЦена` = 1000; в `СоглашенияОЦенообразовании`: `НоменклатураТест` + `КонтрагентТест` → ИндЦена = 700; скидка = 0% | `ПолучитьИтоговуюЦенуСоСкидкой` = 700 | Блокирующий |
| F-13 | `ОпцияИндЦены` = Истина, соглашения нет → fallback на базовую цену | Граничный | `ОпцияИндЦены` = Истина; в `СоглашенияОЦенообразовании` нет записи для пары Номенклатура+Контрагент; скидка = 0% | `ПолучитьИтоговуюЦенуСоСкидкой` = 1000 (базовая) | Высокий |
| F-14 | Скидка применяется поверх индивидуальной цены | Комбинация | `ОпцияИндЦены` = Истина; ИндЦена = 800; скидка = 10%, `МаксСкидка` = 30 | `ПолучитьИтоговуюЦенуСоСкидкой` = 720 (= 800 × 0.90) | Высокий |
| F-15 | Цена на историческую дату | Положительный | В `ЦеныНоменклатуры`: Цена=800 на 2025-01-01, Цена=1000 на 2026-01-01; запрос на дату = 2025-06-01 | `ПолучитьАктуальнуюЦену` = 800 | Высокий |
| F-16 | Цена не найдена в `ЦеныНоменклатуры` → функция не падает | Негативный | Номенклатура без единой записи в регистре; вызов `ПолучитьАктуальнуюЦену` | Возвращает 0 или Неопределено без исключения | Средний |
| F-17 | Все четыре фактора скидки суммируются до потолка | Комбинация | `БазСтавка`=7%, VIP=Да(+5%), `СуммаЗаказа`=100 000(+8%), сезонная акция(+5%); `МаксСкидка`=20 | `РассчитатьСкидку` = 20 (сумма 25%, обрезана до 20) | Высокий |
| F-18 | Изменение `МаксСкидка` влияет на результат без перезапуска | Комбинация | Вызвать `РассчитатьСкидку` при `МаксСкидка`=30 (результат=25); затем изменить `МаксСкидка`=15 и вызвать снова с теми же параметрами | Первый вызов = 25; второй вызов = 15 | Средний |
| F-19 | `ПолучитьИтоговуюЦенуСоСкидкой` с договором без ставки | Негативный | Договор с незаполненной `СтавкаДисконтирования`; VIP=Нет; без акции; скидка = 0% | Функция возвращает базовую цену без исключения | Средний |
| F-20 | `ПрименитьСкидкуКДокументу` на документ с пустой ТЧ | Граничный | Объект документа с нулевым количеством строк в ТЧ «Товары» | Нет исключения; `СуммаДокумента` = 0 | Низкий |
