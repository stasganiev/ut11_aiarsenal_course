## 1. Общее назначение

В модуле две функции — `Расч` и `Расчет` — с практически одинаковой логикой.
`Расч` — старая «сжатая» версия, `Расчет` — более позднее переписывание с защитой от ошибок.

**Обе функции суммируют значения по таблице операций за заданный период в одном из трёх режимов:**

| Режим | Поведение |
|---|---|
| 1 | Простая сумма поля `Сумма` |
| 2 | Сумма, умноженная на коэффициент (`Сумма * Коэф`) |
| 3 | Сумма только по строкам с `Тип = 1` («основной тип операции») |

## 2. Параметры и переменные

### Функция `Расч` (стр. 1)

| Имя | Что это |
|---|---|
| `Т` | Таблица операций (ТЗ или массив структур) |
| `Д1` | Начальная дата периода |
| `Д2` | Конечная дата периода |
| `К` | Режим расчёта (1/2/3) |
| `Врем` | Накопитель суммы (назван «временная», но это и есть итог) |
| `й` | Индекс текущей строки в цикле |
| `Т[й].д` | Дата строки |
| `Т[й].с` | Сумма |
| `Т[й].к` | Коэффициент |
| `Т[й].т` | Тип операции |

### Функция `Расчет` (стр. 25)

| Имя | Что это |
|---|---|
| `тзОпер` | Таблица значений с операциями |
| `нач` | Начало периода |
| `кон` | Конец периода |
| `реж` | Режим расчёта (1/2/3) |
| `сум` | Накопитель суммы |
| `итог` | Финальный результат — дублирует `сум`, не нужен |
| `тмп` | Временное значение `Сумма * Коэф` для режима 2 |
| `к` | Счётчик обработанных строк — нигде наружу не передаётся |
| `й` | Индекс цикла |
| `стр` | Текущая строка ТЗ |
| `орг` | `стр.Документ.Организация` — присваивается, но не используется |
| `д` | Временная переменная для свопа дат |

Поля строки: `стр.Дата`, `стр.Сумма`, `стр.Коэф`, `стр.Тип`, `стр.Документ.Организация`.

## 3. Магические числа и строки

| Литерал | Смысл |
|---|---|
| `К = 1` / `реж = 1` | Режим «простая сумма» |
| `К = 2` / `реж = 2` | Режим «сумма × коэффициент» |
| `К = 3` / `реж = 3` | Режим «только основной тип операции» |
| `Т[й].т = 1` / `стр.Тип = 1` | Значение «основной тип» — скорее всего элемент перечисления, захардкоженный числом |
| `* 1.2` (закомментировано, стр. 82) | Старая ставка НДС 20% |
| `"Нет данных!"` | Нелокализованное UI-сообщение |
| `"Ошибка!"` | Нелокализованное UI-сообщение без контекста |
| `0` как возврат при ошибке | Маскирует ошибку: вызывающий не отличит «реальный 0» от «упало» |

## 4. Проблемы с кодом

### Архитектура / соглашения 1С

- **Конфликт контекстов:** модуль помечен и клиентским, и серверным, но `стр.Документ.Организация` — это разыменование ссылки, требующее серверного контекста. На клиенте такой вызов упадёт.
- **Имена не по стандартам:** `Расч`, `Т`, `Д1`, `Д2`, `К`, `тзОпер`, `нач`, `кон`, `реж`, `й`, `д` — следует использовать осмысленные имена: `ТаблицаОпераций`, `ДатаНачала`, `ДатаОкончания`, `РежимРасчета` и т. д.
- **Нет документации функций** в формате БСП (`// Параметры:`, `// Возвращаемое значение:`).
- **Дублирование:** `Расч` и `Расчет` — одна логика. `Расч` — мёртвый код, подлежит удалению.
- **`Сообщить()` в расчётной функции** нарушает единственную ответственность: функция не должна выводить сообщения пользователю. Сломает фоновые задания и HTTP-сервисы.

### Логика

- **`Попытка/Исключение` с `Возврат 0`** — антипаттерн: глотает любую ошибку. Нужно `ОписаниеОшибки()` + журнал регистрации, либо убрать `Попытка` совсем.
- **Молчаливый своп дат** — изменяет параметры без уведомления. Лучше `ВызватьИсключение` с понятным сообщением.
- **`орг = стр.Документ.Организация`** — переменная не используется, но обращение через `.` выполняется на каждой строке, что создаёт **скрытые запросы к БД в цикле** (проблема O(N) запросов).
- **`итог`, `к`, `тмп`** — лишние переменные, не влияющие на результат.
- **`Перем итог`** с комментарием «на всякий случай» — автор не понимает области видимости в 1С.
- **Вложенные `Иначе → Если`** вместо `ИначеЕсли` — ухудшает читаемость, создаёт лишние уровни отступа.
- **Нет ветки «неизвестный режим»** — при `реж = 5` функция вернёт 0, неотличимо от валидного результата.
- **TODO «доделать обработку отрицательных сумм»** — задача заброшена.
- **Закомментированный код** (стр. 81-83, 100) — нужно удалить.
- **Перебор ТЗ через индекс** вместо `Для Каждого Стр Из тзОпер Цикл` — неидиоматично для 1С.

## 5. Edge-cases, на которых упадёт или соврёт

| # | Ситуация | Что произойдёт |
|---|---|---|
| 1 | `тзОпер = Неопределено` | Возврат 0 через `Сообщить` — обработано, но через UI-сообщение |
| 2 | Пустая ТЗ | Корректно вернёт 0, но без диагностики |
| 3 | `нач` или `кон` = пустая дата (`01.01.0001`) | Всё попадёт в период — тихо неверный результат |
| 4 | `нач` или `кон` — не дата (строка, число) | Исключение → `Возврат 0`, реальная ошибка скрыта |
| 5 | `реж` ∉ {1, 2, 3} | Тихо возвращает 0, неотличимо от пустого результата |
| 6 | Отсутствует колонка `Коэф`/`Тип`/`Сумма`/`Дата`/`Документ` | Исключение → `Возврат 0`, реальная ошибка скрыта |
| 7 | `стр.Коэф = Неопределено` или `NULL` | `Сумма * Неопределено` → исключение → `Возврат 0` |
| 8 | `стр.Документ` — пустая ссылка | Вернёт пустую ссылку без ошибки |
| 9 | `стр.Документ` — ссылка на удалённый объект или реальный документ | **O(N) запросов к БД** в цикле — критическая проблема производительности |
| 10 | `кон` без времени (00:00:00) | Операции этого дня после полуночи **не попадут** в выборку (классическая ошибка границы периода) |
| 11 | Отрицательные суммы | По TODO не обработаны; суммируются как есть — ожидаемо ли? |
| 12 | Очень большая ТЗ | Обращение к `.Организация` на каждой строке → таймаут / деградация |
| 13 | Передача массива структур вместо ТЗ | `.Дата`/`.Сумма` зависят от типа элементов — может упасть |
| 14 | Вызов на клиенте (тонкий клиент) | `стр.Документ.Организация` потребует обращения к серверу — ошибка контекста |
