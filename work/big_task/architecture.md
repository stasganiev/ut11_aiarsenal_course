# Архитектурное решение: автоформирование розничных цен по правилам категорий

> Расширение подсистемы «Ценообразование». База — [паспорт подсистемы](../maps_modules/Ценообразование_sub_description.md) и [task_client.md](task_client.md).

## 1. Цель и границы

Добавить механизм автоматического расчёта розничной цены номенклатуры по правилам, заданным на уровне товарной категории. Расчёт инкапсулируется в существующем модуле `ЦенообразованиеРасчет`; новые метаданные минимальны и не дублируют уже имеющиеся объекты подсистемы.

**В границах задачи:**
- Хранение правил ценообразования по категориям (новый справочник).
- Алгоритм расчёта розничной цены трёх типов (наценка / конкурентная / фиксированная) с защитой минимальной наценкой и округлением.
- Запись результата в `РС.ЦеныНоменклатуры` (вид цены «Розничная»).
- Автоматический пересчёт при изменении закупочной цены.

**Вне границ:** изменение обработки `МассовоеИзменениеЦен` (остаётся как ручной АРМ), скидочные алгоритмы (`РасчётСкидок`, `ПолучитьСкидкиКонтрагента`).

## 2. Решения по расхождениям ТЗ ↔ конфигурация

| В ТЗ | Фактически в конфигурации | Принятое решение |
|---|---|---|
| `СправочникСсылка.КатегорииНоменклатуры`, реквизит `Категория` | `Catalog.ТоварныеКатегории`, реквизит `Номенклатура.ТоварнаяКатегория` | Используем существующие `ТоварныеКатегории` / `ТоварнаяКатегория`. Новый справочник категорий **не создаём**. |
| Виды цен «Закупочная», «Розничная» | `Catalog.ВидыЦен` без нужных предопределённых | Заводим **предопределённые элементы** `Закупочная` и `Розничная` в `Catalog.ВидыЦен`. Код ссылается на них напрямую. |
| Пересчёт «при изменении закупочной цены» | — | **Подписка на событие** `ПриЗаписи` набора записей `РС.ЦеныНоменклатуры`, пересчёт **синхронно** внутри подписки. |

### Запись в `РС.ЦеныНоменклатуры` и регистратор

`РС.ЦеныНоменклатуры` имеет `WriteMode = RecorderSubordinate` — записи подчинены регистратору, набор записывается **по регистратору**. Подписка не имеет под рукой готового документа-регистратора. Решение: для записи розничных цен создаём ссылку на документ-регистратор через `Документы.<ДокументРегистратор>.ПолучитьСсылку()` / `СсылкаНового()`, формируем набор записей с фильтром по этому регистратору и записываем. Регистратор берётся из перечня регистраторов регистра (типовой документ установки цен УТ).

> Защита от рекурсии **не требуется**: подписка работает по событию записи набора `РС.ЦеныНоменклатуры`, но запись розничных цен идёт **по отдельному регистратору** — обработчик в начале отсеивает любые записи с `ВидЦены = Розничная` (и реагирует только на `Закупочная`), повторного «полезного» срабатывания не возникает. Параметр сеанса-флаг из решения исключён.

## 3. Ключевые сущности

### 3.1 Новые объекты подсистемы

| Тип | Имя | Назначение |
|---|---|---|
| Catalog | `ПравилаЦенообразованияКатегорий` | Правила формирования розничной цены, привязанные к товарной категории. Иерархии нет. |
| Enum | `ТипыПравилЦенообразования` | Значения: `ПоНаценке`, `ПоКонкурентнойЦене`, `Фиксированная`. |
| EventSubscription | `ПересчётРозничныхЦенПриИзмененииЗакупочной` | Источник — `РС.ЦеныНоменклатуры`, событие `ПриЗаписи`. |

### 3.2 Структура `Catalog.ПравилаЦенообразованияКатегорий`

Стандартные реквизиты: `Код`, `Наименование`, `ПометкаУдаления`.

Реквизиты:

| Реквизит | Тип | Описание |
|---|---|---|
| `ТоварнаяКатегория` | `СправочникСсылка.ТоварныеКатегории` | Категория, к которой относится правило. Обязательный. |
| `Приоритет` | `Число(3,0)` | Порядок применения внутри категории; меньше — раньше. |
| `ТипПравила` | `ПеречислениеСсылка.ТипыПравилЦенообразования` | Тип расчёта. Обязательный. |
| `Наценка` | `Число(7,2)` | Процент наценки. Используется при `ТипПравила = ПоНаценке`. |
| `Коэффициент` | `Число(7,4)` | Множитель к конкурентной цене. Используется при `ПоКонкурентнойЦене`. |
| `ФиксированнаяЦена` | `Число(15,2)` | Заданное значение цены. Используется при `Фиксированная`. |
| `КонкурентнаяЦена` | `Число(15,2)` | Эталонная цена конкурента. Используется при `ПоКонкурентнойЦене`. |
| `МинимальнаяНаценка` | `Число(7,2)` | Защита от убытков: розничная ≥ закупочная × (1 + МинНаценка/100). |
| `ПравилоОкругления` | `ПеречислениеСсылка.ПравилаОкругления` | Стратегия округления итоговой цены. Переиспользуем существующее перечисление. |
| `Действует` | `Булево` | Признак активности правила. |

> Виды цен в реквизитах правила не хранятся — «Закупочная»/«Розничная» фиксированы в коде (предопределённые элементы `ВидыЦен`).

### 3.3 Переиспользуемые существующие объекты

- `CommonModule.ЦенообразованиеРасчет` — расширяется новыми экспортными методами; ядро не дублируется.
- `Enum.ПравилаОкругления` + `ЦенообразованиеРасчет.ОкруглитьЦену` — округление переиспользуется как есть.
- `РС.ЦеныНоменклатуры` — источник закупочной цены и приёмник розничной (новые предопределённые виды цен).
- `ПараметрыСеанса.КэшЦен` + `ПолучитьБазовуюЦену` / `ПолучитьКэшЦен` / `ОбновитьКэшЦен` — чтение закупочной цены идёт через существующий кэшируемый метод.
- БСП: `ОбщегоНазначения.ЗначениеРеквизитаОбъекта`, `ОбщегоНазначения.ЗначениеРеквизитаОбъектов` (пакетное чтение `ТоварнаяКатегория`), `РегламентныеЗаданияСервер` при необходимости.

### Источники, приёмники, отсутствие рекурсии

- **Закупочная цена** — `РС.ЦеныНоменклатуры`, `ВидЦены = ВидыЦен.Закупочная`, чтение через `ЦенообразованиеРасчет.ПолучитьБазовуюЦену` (с кэшем).
- **Розничная цена** — записывается в `РС.ЦеныНоменклатуры`, `ВидЦены = ВидыЦен.Розничная`, `Период` = период исходной записи закупочной цены. Регистр подчинён регистратору — набор пишется по ссылке на документ-регистратор, полученной через `СсылкаНового()`.
- **Рекурсии нет**: запись розничных цен порождает новое событие `ПриЗаписи`, но обработчик в начале отбирает только строки с `ВидЦены = Закупочная`. В записанном наборе розничных цен таких строк нет — обработчик завершается ранним выходом, не вызывая пересчёт. Параметр сеанса-флаг не нужен.

## 5. Изменения в `CommonModule.ЦенообразованиеРасчет`

Новая область `#Область РозничноеЦенообразование`. Экспортные методы:

| Метод | Назначение |
|---|---|
| `ПересчитатьРозничнуюЦену(Номенклатура, Дата) Экспорт` | Полный цикл для одной номенклатуры: категория → правило → расчёт → запись. Возврат — структура результата (`Цена`, `Применено`, `Основание`). |
| `ПересчитатьРозничныеЦены(МассивНоменклатуры, Дата) Экспорт` | Пакетный пересчёт; точка входа из подписки и из ручных сценариев. |
| `ПолучитьПравилоДляКатегории(ТоварнаяКатегория, Дата) Экспорт` | Возвращает действующее правило с минимальным `Приоритет` для категории. |

Внутренние (служебные) функции: `РассчитатьРозничнуюЦенуПоПравилу`, `ПрименитьМинимальнуюНаценку`, `ЗаписатьРозничнуюЦену`.

## 6. Тестируемость и риски

- Каждый этап (см. [todo_plan.md](todo_plan.md)) даёт самостоятельно проверяемый артефакт: метаданные открываются в Конфигураторе, расчётные функции вызываются изолированно через консоль/обработку, подписка проверяется записью в регистр.
- **Риск рекурсии** закрыт фильтрацией строк набора по `ВидЦены` (запись розницы не порождает полезного срабатывания); обязателен тест «запись закупочной → одна запись розничной, без зацикливания».
- **Риск отсутствия правила/категории** — методы возвращают структуру с `Применено = Ложь` и не пишут регистр; не исключение.
- **Риск накопления регистраторов** — каждый пересчёт создаёт новый документ-регистратор для розничных записей. Для учебной конфигурации допустимо; при необходимости — переиспользовать один служебный регистратор на сеанс/день.
- **Производительность** — пакетный метод читает категории через `ЗначениеРеквизитаОбъектов`, закупочные цены — через `КэшЦен`; правила по категориям читаются одним запросом на пакет.
