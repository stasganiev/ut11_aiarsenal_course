## Этап 2. Ядро расчёта розничной цены (одна номенклатура)

**Что делаем.** В `CommonModule.ЦенообразованиеРасчет` добавляем область `РозничноеЦенообразование` с расчётом цены для одной позиции.

**Входные данные.** Этап 1. Раздел 5 архитектуры. Существующий код модуля (`ПолучитьБазовуюЦену`, `ОкруглитьЦену`).

**Подзадачи.**
- [ ] Добавить `#Область РозничноеЦенообразование` в `CommonModule.ЦенообразованиеРасчет`.
- [ ] `ПолучитьПравилоДляКатегории(ТоварнаяКатегория, Дата) Экспорт` — запрос к `Catalog.ПравилаЦенообразованияКатегорий`: отбор `ТоварнаяКатегория = &Категория И Действует`, упорядочивание по `Приоритет` ВОЗР, `ПЕРВЫЕ 1`; возврат — ссылка на правило или `Неопределено`.
- [ ] `РассчитатьРозничнуюЦенуПоПравилу(Правило, ЗакупочнаяЦена)` (служебная) — `Выбор` по `Правило.ТипПравила`: `ПоНаценке` → `ЗакупочнаяЦена * (1 + Наценка/100)`; `ПоКонкурентнойЦене` → `КонкурентнаяЦена * Коэффициент`; `Фиксированная` → `ФиксированнаяЦена`.
- [ ] `ПрименитьМинимальнуюНаценку(Цена, ЗакупочнаяЦена, МинимальнаяНаценка)` (служебная) — `Макс(Цена, ЗакупочнаяЦена * (1 + МинимальнаяНаценка/100))`.
- [ ] `ПересчитатьРозничнуюЦену(Номенклатура, Дата) Экспорт` — оркестратор: получить `ТоварнаяКатегория` через `ОбщегоНазначения.ЗначениеРеквизитаОбъекта`; получить закупочную цену через `ПолучитьБазовуюЦену(Номенклатура, Справочники.ВидыЦен.Закупочная, Дата)`; получить правило; рассчитать → применить мин. наценку → `ОкруглитьЦену(Цена, Правило.ПравилоОкругления)`.
- [ ] В `ПересчитатьРозничнуюЦену` обработать «пустые» случаи: нет категории / нет правила / нет закупочной цены → вернуть структуру `Применено = Ложь` с понятным `Основание`, регистр **не писать** (запись регистра — Э3, чтобы Э2 был тестируем без побочных эффектов).
- [ ] Возврат `ПересчитатьРозничнуюЦену` — структура с полями `Цена`, `Применено`, `Основание`.
- [ ] Снабдить экспортные методы комментариями по шаблону из `CLAUDE.md`.
- [ ] Проверить из консоли/обработки: `ЦенообразованиеРасчет.ПересчитатьРозничнуюЦену(Товар, ТекущаяДата())` возвращает корректную цену для всех трёх типов правил.

**Результат.** Расчётное ядро вызывается изолированно, без записи в БД, и даёт верную цену для каждого типа правила и при срабатывании минимальной наценки.
