## Этап 1. Метаданные хранения правил

**Что делаем.** Создаём перечисление типов правил и справочник правил ценообразования категорий.

**Входные данные.** Раздел 3 [architecture.md](architecture.md) (структура справочника), доступ к `src/` и Конфигуратору.

**Подзадачи.**
1. Создать `Enum.ТипыПравилЦенообразования` со значениями: `ПоНаценке`, `ПоКонкурентнойЦене`, `Фиксированная`. Синонимы заполнить.
2. Создать `Catalog.ПравилаЦенообразованияКатегорий`:
   - Без иерархии, без владельца.
   - Реквизиты строго по таблице 3.2 архитектуры: `ТоварнаяКатегория` (`СправочникСсылка.ТоварныеКатегории`), `Приоритет` (`Число(3,0)`), `ТипПравила` (`ПеречислениеСсылка.ТипыПравилЦенообразования`), `Наценка` (`Число(7,2)`), `Коэффициент` (`Число(7,4)`), `КонкурентнаяЦена` (`Число(15,2)`), `ФиксированнаяЦена` (`Число(15,2)`), `МинимальнаяНаценка` (`Число(7,2)`), `ПравилоОкругления` (`ПеречислениеСсылка.ПравилаОкругления`), `Действует` (`Булево`).
   - Форма элемента — управляемая; группы реквизитов по `ТипПравила` (видимость `Наценка` / `Коэффициент+КонкурентнаяЦена` / `ФиксированнаяЦена` управляется в `ПриИзмененииТипаПравила`, но это допустимо вынести в Э1 как простую видимость или оставить все поля видимыми — критично только хранение).
3. Включить оба объекта в состав подсистемы `Ценообразование` (`src/Subsystems/Ценообразование.xml`).

**Результат.** Конфигурация открывается без ошибок; можно вручную завести правило для категории в режиме «1С:Предприятие».

**Зависимости.** Нет.

**Сложность.** M

**Что делаем.** Заводим предопределённые элементы `Catalog.ВидыЦен` для закупочной и розничной цены.

**Входные данные.** `src/Catalogs/ВидыЦен.xml`, раздел 2 архитектуры.

**Подзадачи.**
1. Добавить в `Catalog.ВидыЦен` предопределённые элементы `Закупочная` и `Розничная` (имена предопределённых — `Закупочная`, `Розничная`).
2. Проверить заполнение обязательных реквизитов вида цены по правилам УТ 11.5 (валюта, способ задания цены и т.п.) — чтобы элементы были рабочими для записи в `РС.ЦеныНоменклатуры`.
3. Убедиться, что обращение `Справочники.ВидыЦен.Закупочная` / `.Розничная` компилируется.

**Результат.** В коде доступны `Справочники.ВидыЦен.Закупочная` и `Справочники.ВидыЦен.Розничная`; в регистр цен можно записать строку с этими видами.

## Этап 4. Ядро расчёта розничной цены (одна номенклатура)

**Что делаем.** В `CommonModule.ЦенообразованиеРасчет` добавляем область `РозничноеЦенообразование` с расчётом цены для одной позиции.

**Входные данные.** Этапы 1, 2. Раздел 5 архитектуры. Существующий код модуля (`ПолучитьБазовуюЦену`, `ОкруглитьЦену`).

**Подзадачи.**
1. Добавить `#Область РозничноеЦенообразование`.
2. `ПолучитьПравилоДляКатегории(ТоварнаяКатегория, Дата) Экспорт` — запрос к `Catalog.ПравилаЦенообразованияКатегорий`: отбор `ТоварнаяКатегория = &Категория И Действует`, упорядочивание по `Приоритет` ВОЗР, `ПЕРВЫЕ 1`. Возврат — ссылка на правило или `Неопределено`.
3. `РассчитатьРозничнуюЦенуПоПравилу(Правило, ЗакупочнаяЦена)` (служебная) — `Выбор` по `Правило.ТипПравила`:
   - `ПоНаценке` → `ЗакупочнаяЦена * (1 + Правило.Наценка / 100)`;
   - `ПоКонкурентнойЦене` → `Правило.КонкурентнаяЦена * Правило.Коэффициент`;
   - `Фиксированная` → `Правило.ФиксированнаяЦена`.
4. `ПрименитьМинимальнуюНаценку(Цена, ЗакупочнаяЦена, МинимальнаяНаценка)` (служебная) — `Макс(Цена, ЗакупочнаяЦена * (1 + МинимальнаяНаценка / 100))`.
5. `ПересчитатьРозничнуюЦену(Номенклатура, Дата) Экспорт` — оркестратор:
   - получить `ТоварнаяКатегория` через `ОбщегоНазначения.ЗначениеРеквизитаОбъекта`;
   - получить закупочную цену через `ПолучитьБазовуюЦену(Номенклатура, Справочники.ВидыЦен.Закупочная, Дата)`;
   - получить правило; если правила/категории/закупочной цены нет — вернуть структуру `Применено = Ложь` с понятным `Основание`, регистр **не писать**;
   - рассчитать → применить мин. наценку → `ОкруглитьЦену(Цена, Правило.ПравилоОкругления)`;
   - вернуть структуру `Цена`, `Применено`, `Основание` (запись регистра — в Э5, чтобы Э4 был тестируем без побочных эффектов).
6. Снабдить экспортные методы комментариями по шаблону из `CLAUDE.md`.

**Результат.** Из консоли/обработки вызов `ЦенообразованиеРасчет.ПересчитатьРозничнуюЦену(Товар, ТекущаяДата())` возвращает корректную цену для всех трёх типов правил; проверяемо без записи в БД.

**Зависимости.** Э1, Э2.

**Сложность.** L

## Этап 5. Пакетный пересчёт и запись в регистр

**Что делаем.** Добавляем пакетный метод и запись розничной цены в `РС.ЦеныНоменклатуры` под флагом-предохранителем.

**Входные данные.** Этапы 3, 4. Раздел 4 архитектуры.

**Подзадачи.**
1. `ЗаписатьРозничнуюЦену(Номенклатура, Дата, Цена)` (служебная) — менеджер записи `РС.ЦеныНоменклатуры`: `Период = Дата`, `Номенклатура`, `ВидЦены = Справочники.ВидыЦен.Розничная`, `Цена`. Остальные измерения (`Характеристика` и т.п.) — пустые/по умолчанию, согласовать с тем, как пишет существующий `ОбновитьЦеныПоСоглашению`.
2. `ПересчитатьРозничныеЦены(МассивНоменклатуры, Дата) Экспорт`:
   - выставить `ПараметрыСеанса.ВыполняетсяПересчётРозничныхЦен = Истина` внутри `Попытка`;
   - категории пакета прочитать одним вызовом `ОбщегоНазначения.ЗначениеРеквизитаОбъектов`;
   - по каждой позиции: `ПересчитатьРозничнуюЦену` → если `Применено`, то `ЗаписатьРозничнуюЦену`;
   - в `Исключение` / после цикла гарантированно вернуть флаг в `Ложь` (снятие флага — и в успешной ветке, и в `Исключение`);
   - вернуть таблицу/массив результатов по позициям для диагностики.
3. Обернуть запись пакета в транзакцию по образцу `ОбновитьЦеныПоСоглашению`.

**Результат.** Вызов `ПересчитатьРозничныеЦены(Массив, Дата)` создаёт записи розничных цен в `РС.ЦеныНоменклатуры`; флаг сеанса корректно ставится и снимается (проверяется отладчиком).

**Зависимости.** Э3, Э4.

**Сложность.** M

## Этап 6. Подписка на изменение закупочной цены

**Что делаем.** Создаём подписку на событие записи `РС.ЦеныНоменклатуры`, запускающую пересчёт розницы.

**Входные данные.** Этапы 3, 5. Раздел 4 архитектуры.

**Подзадачи.**
1. Создать `EventSubscription.ПересчётРозничныхЦенПриИзмененииЗакупочной`: источник — `РегистрСведений.ЦеныНоменклатуры`, событие — `ПриЗаписи` (набор записей).
2. Обработчик разместить в общем модуле (например, `ЦенообразованиеСобытия` — создать, если подходящего серверного модуля без повторного использования нет; включить в подсистему). Не размещать в `ЦенообразованиеРасчет`, чтобы не смешивать ядро расчёта и инфраструктуру.
3. Логика обработчика:
   - **ранний выход**, если `ПараметрыСеанса.ВыполняетсяПересчётРозничныхЦен = Истина` (рекурсия);
   - собрать из набора записей уникальную номенклатуру строк, где `ВидЦены = Справочники.ВидыЦен.Закупочная`; если таких нет — выход;
   - определить дату пересчёта (период записей);
   - вызвать `ЦенообразованиеРасчет.ПересчитатьРозничныеЦены(МассивНоменклатуры, Дата)`.
4. Учесть `Отказ` / контекст записи набора — пересчёт выполнять для фактически записываемых данных.

**Результат.** Запись закупочной цены в `РС.ЦеныНоменклатуры` (интерактивно или кодом) автоматически порождает запись розничной цены; повторного срабатывания подписки на свою же запись не происходит.

**Зависимости.** Э3, Э5.

**Сложность.** M

## Этап 7. Интеграционная проверка и регрессия

**Что делаем.** Проверяем сценарии целиком и отсутствие регресса в существующем ценообразовании.

**Входные данные.** Этапы 1–6 завершены.

**Подзадачи.**
1. Завести тестовую категорию `ТоварныеКатегории`, привязать к ней номенклатуру через `Номенклатура.ТоварнаяКатегория`.
2. Завести по правилу каждого типа (`ПоНаценке`, `ПоКонкурентнойЦене`, `Фиксированная`), проверить выбор по `Приоритет`.
3. Записать закупочную цену → убедиться, что розничная рассчитана и записана корректно, округление соответствует `ПравилоОкругления`.
4. Проверить срабатывание `МинимальнаяНаценка`: задать правило, дающее цену ниже порога, убедиться, что цена поднята до минимума.
5. Проверить отсутствие рекурсии: один пересчёт на одну запись закупочной цены (отладчик / журнал).
6. Проверить «пустые» сценарии: товар без категории, категория без правил — регистр розницы не пишется, ошибок нет.
7. Регресс: `ЦенообразованиеРасчет.РассчитатьЦену` и `РассчитатьЦеныДокумента` работают как прежде; обработка `МассовоеИзменениеЦен` не затронута.

**Результат.** Все бизнес-требования из [task_client.md](task_client.md) подтверждены на данных; регресса в подсистеме нет.

**Зависимости.** Э1–Э6.

**Сложность.** M
