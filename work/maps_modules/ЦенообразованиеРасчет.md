# Карта модуля `ЦенообразованиеРасчет`

- **Тип:** Общий модуль
- **Контекст выполнения:** Сервер, ВнешнееСоединение (ServerCall = false)
- **Источник:** [src/CommonModules/ЦенообразованиеРасчет/Ext/Module.bsl](../../src/CommonModules/ЦенообразованиеРасчет/Ext/Module.bsl)
- **Назначение:** расчёт цен и скидок по соглашениям/контрагентам, массовое обновление цен, ведение истории расчётов
- **Объём:** ~600 строк, 5 областей, 22 процедуры/функции (4 экспортных + 18 внутренних)

---

## 1. Области модуля

| Область | Назначение |
|---|---|
| `ПрограммныйИнтерфейс` | Публичный API — точки входа для расчёта цены/скидки и массового пересчёта по соглашению. |
| `БазовыеЦены` | Получение базовой цены номенклатуры из регистра, определение вида цены по соглашению, проверка актуальности цены на дату. |
| `Скидки` | Сбор скидок контрагента по приоритетам (акция → объём → категория → постоянство); каждый источник вынесен в отдельную процедуру-добавитель. |
| `ПравилаЦенообразования` | Применение скидок к цене, контроль ограничений (минимальная цена, макс. скидка), округление по правилу соглашения. |
| `СлужебныеПроцедуры` | Кэш цен в параметрах сеанса, запись истории расчётов, вспомогательные конструкторы и нормализаторы. |

---

## 2. Публичный API

### 2.1. `РассчитатьЦену(Товар, Контрагент, Соглашение, ДатаРасчёта, Количество)` — Функция, экспорт

- **Параметры:** ссылка на номенклатуру, контрагента, соглашение; дата расчёта; количество (в текущей реализации не используется в теле).
- **Возвращает:** `Структура` с полями `Цена`, `ПроцентСкидки`, `ПримененныеСкидки` (массив), `Основание` (строка).
- **Назначение:** рассчитать итоговую цену единицы товара для конкретного клиента/соглашения.
- **Кто вызывает (по контексту задачи):** документы «Реализация», «Заказ покупателя» (через свои модули), а также `РассчитатьЦеныДокумента` внутри модуля.

### 2.2. `РассчитатьЦеныДокумента(Документ)` — Функция, экспорт

- **Параметры:** объект документа с табличной частью `Товары` (колонки `Товар`, `Количество`) и реквизитами `Контрагент`, `Соглашение`, `Дата`.
- **Возвращает:** `ТаблицаЗначений` (выгрузка `Товары` + добавленные колонки `ИтоговаяЦена`, `ПроцентСкидки`).
- **Назначение:** расчёт цен по всем строкам документа с применением оптовой скидки.
- **Кто вызывает:** документы «Реализация», «Заказ покупателя».

### 2.3. `ОбновитьЦеныПоСоглашению(Контрагент, ДатаНач, ДатаКон)` — Процедура, экспорт

- **Параметры:** контрагент; границы периода обновления.
- **Возвращает:** —
- **Назначение:** массовая запись новых цен в `РегистрСведений.ЦеныНоменклатуры` по списку товаров из соглашений контрагента; обёрнуто в транзакцию.
- **Кто вызывает:** обработка «Массовое обновление цен».

### 2.4. `РассчитатьСкидку(Клиент, Договор, СуммаЗаказа, ДатаЗаказа)` — Функция, экспорт

- **Параметры:** контрагент; договор; сумма заказа; дата.
- **Возвращает:** `Число` — итоговый процент скидки с учётом ограничения максимума.
- **Назначение:** агрегированная скидка для клиента (база по договору + скидки контрагента + бонус 5% при сумме > 100 000).
- **Кто вызывает:** документы «Заказ покупателя», «Реализация».

## 3. Внутренние процедуры/функции (контракты)

### Область `Скидки` (после доработки)

| Имя | Тип | Контракт |
|---|---|---|
| `ПолучитьСкидкиКонтрагента(Контрагент, ДатаРасчёта)` | Функция | Возвращает `Массив` структур `{ТипСкидки, Процент, Основание}`. Однократно читает реквизит `Категория`, затем последовательно вызывает 4 добавителя по приоритету: акция → объём → категория → постоянство. |
| `ДобавитьСкидкуПоАкции(Скидки, ДатаРасчёта)` | Процедура | Добавляет в `Скидки` элемент `Акция`, если `ПроверитьАкцию` вернула > 0. Параметр `Скидки` изменяется по месту. |
| `ДобавитьСкидкуПоОбъёму(Скидки, Контрагент, ДатаРасчёта)` | Процедура | Считает скидку за объём закупок за 3 предшествующих месяца через `РассчитатьСкидкуПоОбъёму`; добавляет элемент `Объём`, если > 0. |
| `ДобавитьСкидкуПоКатегории(Скидки, Категория)` | Процедура | Добавляет один из элементов: `VIP` (+5%), `Новый клиент` (+2%) — по значению перечисления `КатегорииКлиентов`. |
| `ДобавитьСкидкуЗаПостоянство(Скидки, Контрагент, ДатаРасчёта)` | Процедура | **Новое.** Добавляет `Постоянный клиент` (+3%), если `ЕстьИсторияОтношенийДольше12Месяцев` = `Истина`. |
| `ЕстьИсторияОтношенийДольше12Месяцев(Контрагент, ДатаРасчёта)` | Функция | **Новое.** Возвращает `Булево`. Делает запрос к `РегистрНакопления.Закупки.Обороты` за период `[ДатаРасчёта-12мес., ДатаРасчёта]`, проверяет `СУММА(СуммаОборот) > 0`. |
| `РассчитатьСкидкуПоОбъёму(Контрагент, Период)` | Функция | Возвращает `Число` (0/2/4/7) по порогам 100k/500k/1M суммы закупок за `Период`. |
| `ПроверитьАкцию(Товар, ДатаРасчёта)` | Функция | Возвращает `Число` — максимальный процент акции, действующей на дату; для `Товар = Неопределено` ищет по «общим» акциям с пустой номенклатурой. |
| `ОптоваяСкидкаПоДокументу(ТабличнаяЧасть)` | Функция | Возвращает `Число` (0/1/3/5) по порогам 50k/200k/500k суммы документа. |
| `ПрименитьНакопительнуюСкидку(Контрагент, БазоваяСкидка)` | Функция | **Мёртвый код.** Не вызывается. |

### Область `БазовыеЦены`

| Имя | Тип | Контракт |
|---|---|---|
| `ПолучитьБазовуюЦену(Товар, ВидЦены, ДатаРасчёта)` | Функция | Возвращает `Число` или 0. Сначала смотрит в кэш сеанса; иначе делает срез по `ЦеныНоменклатуры` и проверяет `ЦенаДействуетНаДату`. |
| `ПолучитьВидЦеныПоСоглашению(Соглашение)` | Функция | Возвращает `СправочникСсылка.ВидыЦен`. По незаполненному соглашению — `Основная`. |
| `ЦенаДействуетНаДату(ЗаписьЦены, ДатаПроверки)` | Функция | Возвращает `Булево`. Цена считается актуальной, если её период не в будущем и не старше 365 дней. |

### Область `ПравилаЦенообразования`

| Имя | Тип | Контракт |
|---|---|---|
| `ПрименитьПравилаЦенообразования(Цена, Скидки, Соглашение)` | Функция | Суммирует проценты скидок, применяет к цене и поднимает до `Соглашение.МинимальнаяЦена`. |
| `ПроверитьОграничения(ИтоговаяЦена, МинимальнаяЦена, МаксимальнаяСкидка)` | Функция | Поднимает цену до минимальной; защищает от отрицательной цены. |
| `ОкруглитьЦену(Цена, ПравилоОкругления)` | Функция | По значению перечисления `ПравилаОкругления`: `ДоРубля` / `До10` / `Психологическое99`. |

### Область `СлужебныеПроцедуры`

| Имя | Тип | Контракт |
|---|---|---|
| `ПолучитьКэшЦен / ОбновитьКэшЦен` | Функция/Процедура | Чтение/запись `ПараметрыСеанса.КэшЦен` по ключу `<товар>|<видЦены>|<дата>`. |
| `ЗаписатьИсториюРасчёта(ДанныеРасчёта)` | Процедура | Запись в `РегистрСведений.ИсторияРасчётаЦен`; ошибки логирует в журнал. |
| `ПодготовитьСтруктуруРезультата` | Функция | Фабрика структуры результата для `РассчитатьЦену`. |
| `ПолучитьБазовуюСкидку(Договор)` | Функция | Читает реквизит `СкидкаПоУмолчанию` договора. |
| `ОграничитьМаксимальнуюСкидку(Скидка)` | Функция | Клампит скидку в `[0; Константы.МаксимальнаяСкидкаПоУмолчанию или 25]`. |
| `СвернутьПроцентСкидки(Скидки)` | Функция | Сумма процентов по массиву скидок. |

## 4. Граф зависимостей (только реальные вызовы из кода)

### 4.1. `РассчитатьЦену`
```
РассчитатьЦену
├── ПодготовитьСтруктуруРезультата()
├── ПолучитьВидЦеныПоСоглашению(Соглашение)
│   └── ОбщегоНазначения.ЗначениеРеквизитаОбъекта   [БСП]
├── ПолучитьБазовуюЦену(Товар, ВидЦены, ДатаРасчёта)
│   ├── ПолучитьКэшЦен(Товар, ВидЦены, ДатаРасчёта)
│   ├── [Запрос] РегистрСведений.ЦеныНоменклатуры.СрезПоследних
│   ├── ЦенаДействуетНаДату(Выборка, ДатаРасчёта)
│   └── ОбновитьКэшЦен(Товар, ВидЦены, ДатаРасчёта, Цена)
├── ПолучитьСкидкиКонтрагента(Контрагент, ДатаРасчёта)
│   ├── ОбщегоНазначения.ЗначениеРеквизитаОбъекта   [БСП]   (однократно — реквизит «Категория»)
│   ├── ДобавитьСкидкуПоАкции(Скидки, ДатаРасчёта)
│   │   └── ПроверитьАкцию(Неопределено, ДатаРасчёта)
│   │       └── [Запрос] Справочник.Акции
│   ├── ДобавитьСкидкуПоОбъёму(Скидки, Контрагент, ДатаРасчёта)
│   │   └── РассчитатьСкидкуПоОбъёму(Контрагент, Период)
│   │       └── [Запрос] РегистрНакопления.Закупки.Обороты
│   ├── ДобавитьСкидкуПоКатегории(Скидки, Категория)
│   └── ДобавитьСкидкуЗаПостоянство(Скидки, Контрагент, ДатаРасчёта)         [НОВОЕ]
│       └── ЕстьИсторияОтношенийДольше12Месяцев(Контрагент, ДатаРасчёта)     [НОВОЕ]
│           └── [Запрос] РегистрНакопления.Закупки.Обороты
├── ПрименитьПравилаЦенообразования(БазоваяЦена, Скидки, Соглашение)
├── ПроверитьОграничения(Цена, Соглашение.МинимальнаяЦена, 25)
├── ОкруглитьЦену(Цена, Соглашение.ПравилоОкругления)
├── СвернутьПроцентСкидки(Скидки)
└── ЗаписатьИсториюРасчёта(...)
    └── РегистрСведений.ИсторияРасчётаЦен.СоздатьНаборЗаписей + ЗаписьЖурналаРегистрации
```

### 4.2. `РассчитатьЦеныДокумента`
```
РассчитатьЦеныДокумента
├── РассчитатьЦену(...)               [см. 4.1 — вызывается в цикле по строкам]
└── ОптоваяСкидкаПоДокументу(Результат)
```

### 4.3. `ОбновитьЦеныПоСоглашению`
```
ОбновитьЦеныПоСоглашению
├── [Запрос] РегистрСведений.СоглашенияОЦенообразовании.СрезПоследних
├── ПолучитьБазовуюЦену(Товар, ВидЦены, ДатаКон)   [см. 4.1]
└── РегистрСведений.ЦеныНоменклатуры.СоздатьМенеджерЗаписи + Записать
    (НачатьТранзакцию / ЗафиксироватьТранзакцию / ОтменитьТранзакцию)
```

### 4.4. `РассчитатьСкидку`
```
РассчитатьСкидку
├── ПолучитьСкидкиКонтрагента(Клиент, ДатаЗаказа)   [см. 4.1]
├── ПолучитьБазовуюСкидку(Договор)
│   └── ОбщегоНазначения.ЗначениеРеквизитаОбъекта   [БСП]
└── ОграничитьМаксимальнуюСкидку(ОбщийПроцент)
    └── Константы.МаксимальнаяСкидкаПоУмолчанию.Получить()
```

### 4.5. Несвязанные с публичным API (не вызываются из модуля)

- `ПрименитьНакопительнуюСкидку(Контрагент, БазоваяСкидка)` — определена, но **не вызывается** ни из одной экспортной/внутренней процедуры модуля. Кандидат на удаление либо подключение в `РассчитатьСкидку`.

## 5. Внешние зависимости

### 5.1. Регистры сведений
- `РегистрСведений.ЦеныНоменклатуры` — `СрезПоследних` в `ПолучитьБазовуюЦену`; запись через `СоздатьМенеджерЗаписи` в `ОбновитьЦеныПоСоглашению`.
- `РегистрСведений.СоглашенияОЦенообразовании` — `СрезПоследних` в `ОбновитьЦеныПоСоглашению`.
- `РегистрСведений.ИсторияРасчётаЦен` — запись `НаборЗаписей` в `ЗаписатьИсториюРасчёта`.

### 5.2. Регистры накопления
- `РегистрНакопления.Закупки.Обороты` — используется в **трёх** функциях:
  - `РассчитатьСкидкуПоОбъёму` (период 3 мес.),
  - `ЕстьИсторияОтношенийДольше12Месяцев` (период 12 мес.) — **новое**,
  - `ПрименитьНакопительнуюСкидку` (без границ периода) — мёртвый код.

### 5.3. Справочники
- `Справочник.Акции` — запрос в `ПроверитьАкцию` (поля `ДатаНачала`, `ДатаОкончания`, `Товар`, `ПроцентСкидки`).
- `Справочник.ВидыЦен` — предопределённый элемент `Основная` в `ПолучитьВидЦеныПоСоглашению`.
- `Справочник.Номенклатура` — `ПустаяСсылка()` в `ПроверитьАкцию`.

### 5.4. Перечисления
- `Перечисления.КатегорииКлиентов.VIP`, `Перечисления.КатегорииКлиентов.Новый` — в `ДобавитьСкидкуПоКатегории`.
- `Перечисления.ПравилаОкругления.ДоРубля`, `.До10`, `.Психологическое99` — в `ОкруглитьЦену`.

### 5.5. Константы
- `Константы.МаксимальнаяСкидкаПоУмолчанию` — в `ОграничитьМаксимальнуюСкидку`.

### 5.6. Параметры сеанса
- `ПараметрыСеанса.КэшЦен` — чтение и запись (`ПолучитьКэшЦен`, `ОбновитьКэшЦен`).

### 5.7. Внешний код БСП / платформы
- `ОбщегоНазначения.ЗначениеРеквизитаОбъекта` — в `ПолучитьВидЦеныПоСоглашению`, `ПолучитьСкидкиКонтрагента` (теперь **однократно**), `ПолучитьБазовуюСкидку`.
- `ЗаписьЖурналаРегистрации`, `УровеньЖурналаРегистрации.Предупреждение` — в `ЗаписатьИсториюРасчёта`.
- `ТекущаяДата()` — в `ЗаписатьИсториюРасчёта` (на сервере; обычно используют `ТекущаяДатаСеанса()`).
- `ДобавитьМесяц`, `Новый СтандартныйПериод` — в `ДобавитьСкидкуПоОбъёму`, `ЕстьИсторияОтношенийДольше12Месяцев`.

### 5.8. Реквизиты объектов, читаемые напрямую (без `ЗначениеРеквизитаОбъекта`)
- `Соглашение.МинимальнаяЦена`, `Соглашение.ПравилоОкругления`, `Соглашение.Наименование` — в `РассчитатьЦену`, `ПрименитьПравилаЦенообразования`.
- `Документ.Товары`, `Документ.Контрагент`, `Документ.Соглашение`, `Документ.Дата` — в `РассчитатьЦеныДокумента`.

## 6. Горячие точки

Подсчёт по реальным вызовам в модуле (входящие = откуда вызывают; исходящие = что вызывает сама процедура, включая запросы к БД и БСП).

| Процедура / Функция | Входящие | Исходящие | Связей всего | Комментарий |
|---|---:|---:|---:|---|
| **`РассчитатьЦену`** | 2 (`РассчитатьЦеныДокумента`, внешние документы) | 9 | **11** | Главный оркестратор расчёта — без изменений. |
| **`ПолучитьСкидкиКонтрагента`** | 2 (`РассчитатьЦену`, `РассчитатьСкидку`) | 5 (БСП + 4 добавителя) | **7** ↑ | Перестроена: теперь **диспетчер** добавителей по приоритетам. Стала ещё «более горячей» — это центр расширения для новых правил скидок. |
| **`ПолучитьБазовуюЦену`** | 2 (`РассчитатьЦену`, `ОбновитьЦеныПоСоглашению`) | 4 (кэш ×2, запрос, `ЦенаДействуетНаДату`) | **6** | Без изменений. |
| `РегистрНакопления.Закупки.Обороты` (как ресурс) | 3 функции-потребителя | — | **3** ↑ | Новое: появился третий потребитель (`ЕстьИсторияОтношенийДольше12Месяцев`). При оптимизации скидок имеет смысл рассмотреть единый запрос-провайдер вместо трёх независимых обращений. |
| `ДобавитьСкидкуПоАкции` / `…ПоОбъёму` / `…ПоКатегории` / `…ЗаПостоянство` | 1 (`ПолучитьСкидкиКонтрагента`) | 1–2 | 2–3 | **Новые** точки расширения. Каждая независима — добавлять/убирать правила можно не трогая `ПолучитьСкидкиКонтрагента` по существу. |
| `ЕстьИсторияОтношенийДольше12Месяцев` | 1 (`ДобавитьСкидкуЗаПостоянство`) | 1 (запрос) | 2 | **Новое.** Единственный потребитель — `ДобавитьСкидкуЗаПостоянство`. |
| `ОбновитьКэшЦен` / `ПолучитьКэшЦен` | 1 каждая | 1 | 2 | Без изменений. |
| `ЗаписатьИсториюРасчёта` | 1 (`РассчитатьЦену`) | 2 | 3 | Без изменений. |
| `ПрименитьНакопительнуюСкидку` | **0** | 1 | 1 | Мёртвый код — без изменений. |

## 7. Замечания, выявленные при построении карты

Зафиксированы как побочный результат — не часть карты, но полезны для последующего ревью:

1. ~~`ПолучитьСкидкиКонтрагента`: реквизит `Категория` читается дважды.~~ **Исправлено в коммите `096dc1c6b`** — теперь одно чтение.
2. `ПрименитьНакопительнуюСкидку` — мёртвый код, не подключён даже после доработки системы скидок (хотя ниша «накопительная по обороту» теперь занята «постоянством отношений»).
3. `РассчитатьЦену`: параметр `Количество` принимается, но в теле не используется.
4. `ПроверитьОграничения` вызывается с жёстко зашитой константой `25` — игнорируется значение из `Константы.МаксимальнаяСкидкаПоУмолчанию`.
5. `ЗаписатьИсториюРасчёта` использует `ТекущаяДата()`, а не `ТекущаяДатаСеанса()`.
6. `ПрименитьПравилаЦенообразования` и `ПроверитьОграничения` дублируют проверку минимальной цены.
7. **Новое:** `РассчитатьСкидкуПоОбъёму` и `ЕстьИсторияОтношенийДольше12Месяцев` делают почти идентичные запросы к `Закупки.Обороты` по одному контрагенту, отличающиеся только границами периода. Кандидат на объединение в один запрос-провайдер с предвыборкой данных.
8. **Новое:** Комментарий в `ПолучитьСкидкиКонтрагента` декларирует порядок приоритетов «акция > объём > категория > постоянство», но **порядок добавления в массив не влияет на итоговую цену** — `ПрименитьПравилаЦенообразования` просто суммирует проценты. «Приоритет» здесь означает только порядок в результирующем массиве для UI/отчётности.
