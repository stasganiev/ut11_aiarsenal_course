# Карта модуля `ЦенообразованиеРасчет`

- **Тип:** Общий модуль
- **Контекст выполнения:** Сервер, ВнешнееСоединение (ServerCall = false)
- **Источник:** [src/CommonModules/ЦенообразованиеРасчет/Ext/Module.bsl](../../src/CommonModules/ЦенообразованиеРасчет/Ext/Module.bsl)
- **Назначение:** расчёт цен и скидок по соглашениям/контрагентам, массовое обновление цен, ведение истории расчётов
- **Объём:** ~500 строк, 4 области, 17 процедур/функций (4 экспортных + 13 внутренних)

---

## 1. Области модуля

| Область | Назначение |
|---|---|
| `ПрограммныйИнтерфейс` | Публичный API — точки входа для расчёта цены/скидки и массового пересчёта по соглашению. |
| `БазовыеЦены` | Получение базовой цены номенклатуры из регистра, определение вида цены по соглашению, проверка актуальности цены на дату. |
| `Скидки` | Сбор скидок контрагента (VIP, новый клиент, объёмная, акционная, накопительная) по разным источникам данных. |
| `ПравилаЦенообразования` | Применение скидок к цене, контроль ограничений (минимальная цена, макс. скидка), округление по правилу соглашения. |
| `СлужебныеПроцедуры` | Кэш цен в параметрах сеанса, запись истории расчётов, вспомогательные конструкторы и нормализаторы. |

---

## 2. Публичный API

### 2.1. `РассчитатьЦену(Товар, Контрагент, Соглашение, ДатаРасчёта, Количество)` — Функция, экспорт

- **Параметры:** ссылка на номенклатуру, контрагента, соглашение; дата расчёта; количество (в текущей реализации не используется в теле).
- **Возвращает:** `Структура` с полями `Цена`, `ПроцентСкидки`, `ПримененныеСкидки` (массив), `Основание` (строка).
- **Назначение:** рассчитать итоговую цену единицы товара для конкретного клиента/соглашения.
- **Кто вызывает (по контексту задачи):** документы «Реализация», «Заказ покупателя» (через свои модули), а также `РассчитатьЦеныДокумента` внутри модуля.

### 2.2. `РассчитатьЦеныДокумента(Документ)` — Функция, экспорт

- **Параметры:** объект документа с табличной частью `Товары` (колонки `Товар`, `Количество`) и реквизитами `Контрагент`, `Соглашение`, `Дата`.
- **Возвращает:** `ТаблицаЗначений` (выгрузка `Товары` + добавленные колонки `ИтоговаяЦена`, `ПроцентСкидки`).
- **Назначение:** расчёт цен по всем строкам документа с применением оптовой скидки.
- **Кто вызывает:** документы «Реализация», «Заказ покупателя».

### 2.3. `ОбновитьЦеныПоСоглашению(Контрагент, ДатаНач, ДатаКон)` — Процедура, экспорт

- **Параметры:** контрагент; границы периода обновления.
- **Возвращает:** —
- **Назначение:** массовая запись новых цен в `РегистрСведений.ЦеныНоменклатуры` по списку товаров из соглашений контрагента; обёрнуто в транзакцию.
- **Кто вызывает:** обработка «Массовое обновление цен».

### 2.4. `РассчитатьСкидку(Клиент, Договор, СуммаЗаказа, ДатаЗаказа)` — Функция, экспорт

- **Параметры:** контрагент; договор; сумма заказа; дата.
- **Возвращает:** `Число` — итоговый процент скидки с учётом ограничения максимума.
- **Назначение:** агрегированная скидка для клиента (база по договору + скидки контрагента + бонус 5% при сумме > 100 000).
- **Кто вызывает:** документы «Заказ покупателя», «Реализация».

## 3. Граф зависимостей (только реальные вызовы из кода)

### 3.1. `РассчитатьЦену`
```
РассчитатьЦену
├── ПодготовитьСтруктуруРезультата()
├── ПолучитьВидЦеныПоСоглашению(Соглашение)
│   └── ОбщегоНазначения.ЗначениеРеквизитаОбъекта   [БСП]
├── ПолучитьБазовуюЦену(Товар, ВидЦены, ДатаРасчёта)
│   ├── ПолучитьКэшЦен(Товар, ВидЦены, ДатаРасчёта)
│   ├── [Запрос] РегистрСведений.ЦеныНоменклатуры.СрезПоследних
│   ├── ЦенаДействуетНаДату(Выборка, ДатаРасчёта)
│   └── ОбновитьКэшЦен(Товар, ВидЦены, ДатаРасчёта, Цена)
├── ПолучитьСкидкиКонтрагента(Контрагент, ДатаРасчёта)
│   ├── ОбщегоНазначения.ЗначениеРеквизитаОбъекта   [БСП] (×2 — дублирующее чтение «Категория»)
│   ├── РассчитатьСкидкуПоОбъёму(Контрагент, Период)
│   │   └── [Запрос] РегистрНакопления.Закупки.Обороты
│   └── ПроверитьАкцию(Неопределено, ДатаРасчёта)
│       └── [Запрос] Справочник.Акции
├── ПрименитьПравилаЦенообразования(БазоваяЦена, Скидки, Соглашение)
├── ПроверитьОграничения(Цена, Соглашение.МинимальнаяЦена, 25)
├── ОкруглитьЦену(Цена, Соглашение.ПравилоОкругления)
├── СвернутьПроцентСкидки(Скидки)
└── ЗаписатьИсториюРасчёта(...)
    └── РегистрСведений.ИсторияРасчётаЦен.СоздатьНаборЗаписей + ЗаписьЖурналаРегистрации
```

### 3.2. `РассчитатьЦеныДокумента`
```
РассчитатьЦеныДокумента
├── РассчитатьЦену(...)               [см. 3.1 — вызывается в цикле по строкам]
└── ОптоваяСкидкаПоДокументу(Результат)
```

### 3.3. `ОбновитьЦеныПоСоглашению`
```
ОбновитьЦеныПоСоглашению
├── [Запрос] РегистрСведений.СоглашенияОЦенообразовании.СрезПоследних
├── ПолучитьБазовуюЦену(Товар, ВидЦены, ДатаКон)   [см. 3.1]
└── РегистрСведений.ЦеныНоменклатуры.СоздатьМенеджерЗаписи + Записать
    (НачатьТранзакцию / ЗафиксироватьТранзакцию / ОтменитьТранзакцию)
```

### 3.4. `РассчитатьСкидку`
```
РассчитатьСкидку
├── ПолучитьСкидкиКонтрагента(Клиент, ДатаЗаказа)   [см. 3.1]
├── ПолучитьБазовуюСкидку(Договор)
│   └── ОбщегоНазначения.ЗначениеРеквизитаОбъекта   [БСП]
└── ОграничитьМаксимальнуюСкидку(ОбщийПроцент)
    └── Константы.МаксимальнаяСкидкаПоУмолчанию.Получить()
```

### 3.5. Несвязанные с публичным API (не вызываются из модуля)

- `ПрименитьНакопительнуюСкидку(Контрагент, БазоваяСкидка)` — определена, но **не вызывается** ни из одной экспортной/внутренней процедуры модуля. Кандидат на удаление либо подключение в `РассчитатьСкидку`.

## 4. Внешние зависимости

### 4.1. Регистры сведений
- `РегистрСведений.ЦеныНоменклатуры` — `СрезПоследних` в `ПолучитьБазовуюЦену`; запись через `СоздатьМенеджерЗаписи` в `ОбновитьЦеныПоСоглашению`.
- `РегистрСведений.СоглашенияОЦенообразовании` — `СрезПоследних` в `ОбновитьЦеныПоСоглашению`.
- `РегистрСведений.ИсторияРасчётаЦен` — запись `НаборЗаписей` в `ЗаписатьИсториюРасчёта`.

### 4.2. Регистры накопления
- `РегистрНакопления.Закупки` — таблица `Обороты` в `РассчитатьСкидкуПоОбъёму` и `ПрименитьНакопительнуюСкидку`.

### 4.3. Справочники
- `Справочник.Акции` — запрос в `ПроверитьАкцию` (поля `ДатаНачала`, `ДатаОкончания`, `Товар`, `ПроцентСкидки`).
- `Справочник.ВидыЦен` — предопределённый элемент `Основная` в `ПолучитьВидЦеныПоСоглашению`.
- `Справочник.Номенклатура` — `ПустаяСсылка()` в `ПроверитьАкцию`.

### 4.4. Перечисления
- `Перечисления.КатегорииКлиентов.VIP`, `Перечисления.КатегорииКлиентов.Новый` — в `ПолучитьСкидкиКонтрагента`.
- `Перечисления.ПравилаОкругления.ДоРубля`, `.До10`, `.Психологическое99` — в `ОкруглитьЦену`.

### 4.5. Константы
- `Константы.МаксимальнаяСкидкаПоУмолчанию` — в `ОграничитьМаксимальнуюСкидку`.

### 4.6. Параметры сеанса
- `ПараметрыСеанса.КэшЦен` — чтение и запись (`ПолучитьКэшЦен`, `ОбновитьКэшЦен`). **Запись через `ПараметрыСеанса.КэшЦен = …` — потенциальный риск, требует уточнения политики установки.**

### 4.7. Внешний код БСП / платформы
- `ОбщегоНазначения.ЗначениеРеквизитаОбъекта` — в `ПолучитьВидЦеныПоСоглашению`, `ПолучитьСкидкиКонтрагента` (×2), `ПолучитьБазовуюСкидку`.
- `ЗаписьЖурналаРегистрации`, `УровеньЖурналаРегистрации.Предупреждение` — в `ЗаписатьИсториюРасчёта`.
- `ТекущаяДата()` — в `ЗаписатьИсториюРасчёта` (на сервере; стоит обратить внимание — обычно используют `ТекущаяДатаСеанса()`).
- `ДобавитьМесяц`, `Новый СтандартныйПериод` — в `ПолучитьСкидкиКонтрагента`.

### 4.8. Реквизиты объектов, читаемые напрямую (без `ЗначениеРеквизитаОбъекта`)
- `Соглашение.МинимальнаяЦена`, `Соглашение.ПравилоОкругления`, `Соглашение.Наименование` — в `РассчитатьЦену`, `ПрименитьПравилаЦенообразования`.
- `Документ.Товары`, `Документ.Контрагент`, `Документ.Соглашение`, `Документ.Дата` — в `РассчитатьЦеныДокумента`.

## 5. Горячие точки

Подсчёт по реальным вызовам в модуле (входящие = откуда вызывают; исходящие = что вызывает сама процедура, включая запросы к БД и БСП).

| Процедура / Функция | Входящие | Исходящие | Связей всего | Комментарий |
|---|---:|---:|---:|---|
| **`РассчитатьЦену`** | 2 (`РассчитатьЦеныДокумента`, внешние документы) | 9 | **11** | Главный оркестратор расчёта — самая «тяжёлая» точка. |
| **`ПолучитьБазовуюЦену`** | 2 (`РассчитатьЦену`, `ОбновитьЦеныПоСоглашению`) | 4 (кэш ×2, запрос, `ЦенаДействуетНаДату`) | **6** | Точка консолидации чтения цен — изменения здесь затрагивают и онлайн-расчёт, и массовое обновление. |
| **`ПолучитьСкидкиКонтрагента`** | 2 (`РассчитатьЦену`, `РассчитатьСкидку`) | 4 (БСП ×2, `РассчитатьСкидкуПоОбъёму`, `ПроверитьАкцию`) | **6** | Точка слияния разнородных источников скидок; содержит дублирующее чтение «Категория». |
| `ОбновитьКэшЦен` / `ПолучитьКэшЦен` | 1 каждая (`ПолучитьБазовуюЦену`) | 1 (ПараметрыСеанса) | 2 | Связаны через общую структуру ключа — менять только парой. |
| `ЗаписатьИсториюРасчёта` | 1 (`РассчитатьЦену`) | 2 (регистр + журнал) | 3 | Единственный писатель в `ИсторияРасчётаЦен`. |
| `ПрименитьНакопительнуюСкидку` | **0** | 1 (запрос) | 1 | **Мёртвый код** — не вызывается. |

**Вывод по горячим точкам:** при любом изменении логики расчёта первым делом смотреть `РассчитатьЦену` → далее `ПолучитьБазовуюЦену` и `ПолучитьСкидкиКонтрагента`. Эти три процедуры покрывают практически весь поток данных модуля.

## 6. Замечания, выявленные при построении карты

Зафиксированы как побочный результат — не часть карты, но полезны для последующего ревью:

1. `ПолучитьСкидкиКонтрагента`: реквизит `Категория` читается через `ОбщегоНазначения.ЗначениеРеквизитаОбъекта` дважды подряд (строки 195 и 202) — лишний round-trip к БД.
2. `ПрименитьНакопительнуюСкидку` — мёртвый код.
3. `РассчитатьЦену`: параметр `Количество` принимается, но в теле не используется (передаётся в строку `Стр.Количество` только в `РассчитатьЦеныДокумента` для подсчёта суммы документа).
4. `ПроверитьОграничения` вызывается с жёстко зашитой константой `25` — игнорируется значение из `Константы.МаксимальнаяСкидкаПоУмолчанию`.
5. `ЗаписатьИсториюРасчёта` использует `ТекущаяДата()` (системное время сервера), а не `ТекущаяДатаСеанса()` — потенциальное расхождение часовых поясов.
6. `ПрименитьПравилаЦенообразования` и `ПроверитьОграничения` дублируют проверку минимальной цены.
