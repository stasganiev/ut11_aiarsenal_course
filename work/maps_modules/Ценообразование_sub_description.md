# Паспорт подсистемы «Ценообразование» (обновлённый)

> База — [subsystem_description.md](../doctech/subsystem_description.md). Здесь дополнены объекты, появившиеся в составе подсистемы после первой версии паспорта. Перечень объектов сверен с [Subsystems/Ценообразование.xml](../../src/Subsystems/Ценообразование.xml).

## Назначение

Подсистема рассчитывает итоговую цену реализации единицы номенклатуры для конкретного контрагента: определяет базовую цену по виду цены и соглашению, накладывает многоуровневые скидки (акция, объём закупок, категория клиента, постоянство отношений, оптовая по сумме документа), применяет правила округления и ограничение по минимальной цене / максимальной скидке, поддерживает массовое изменение цен и пакетную обработку неотгруженных заказов.

## Новые объекты подсистемы

### Общие модули

#### CommonModule.ОбработкаЗаказов

**Бизнес-смысл.** Регламентная пакетная обработка непроведённых документов реализации за период: для каждого заказа подтягивает категорию и договор контрагента, рассчитывает скидку через `РасчётСкидок.РассчитатьСкидку`, переписывает суммы строк, применяет дополнительный 5%-вычет к крупным заказам (>100 000) и проводит документ.

**Назначение в подсистеме.** Точка входа из регламентного задания «Ночная обработка заказов»; связывает расчёт скидок с фактической записью документов продажи. Также предоставляет функцию `ПересчитатьИтогиПоКонтрагенту(Контрагент, Период)` — сумма оборотов по регистру `Продажи` за месяц, используется и в регламенте, и при ручном пересчёте.

#### CommonModule.ЦенообразованиеРасчет

**Бизнес-смысл.** Расширенное ядро расчёта цены: возвращает структуру с итоговой ценой, суммарным процентом скидки, списком применённых скидок и текстовым основанием. Учитывает приоритеты скидок (акция → объём → категория → постоянство), накладывает минимальную цену из соглашения, ограничивает максимальную скидку константой и округляет результат по правилу из соглашения.

**Назначение в подсистеме.** Альтернативный (более полный, чем `РасчётСкидок`) сценарий ценообразования с детализацией основания, кэшированием базовой цены через `ПараметрыСеанса.КэшЦен`, ведением `РегистрСведений.ИсторияРасчётаЦен` и массовым пересчётом по табличной части документа (`РассчитатьЦеныДокумента`) и по индивидуальным соглашениям контрагента (`ОбновитьЦеныПоСоглашению`).

### Обработки

#### DataProcessor.МассовоеИзменениеЦен

**Бизнес-смысл.** АРМ для массового пересмотра цен номенклатуры: пользователь выбирает группу номенклатуры, вид цены, дату установки, задаёт процент изменения и шаг округления, получает таблицу «текущая цена → новая цена» и записывает изменения в регистр `ЦеныНоменклатуры` одной операцией.

**Назначение в подсистеме.** Ручной интерфейс администрирования базовых цен — отвечает за пакетное формирование записей регистра цен, на которые затем опираются модули расчёта (`ПолучитьБазовуюЦену`).

### Справочники

#### Catalog.Акции

**Бизнес-смысл.** Справочник маркетинговых акций со сроком действия (`ДатаНачала`, `ДатаОкончания`), привязкой к товару (или пустой ссылкой — общерыночная акция) и процентом скидки. Хранит правила «временных» скидок, действующих в рамках кампаний.

**Назначение в подсистеме.** Источник данных для шага «Приоритет 1 — действующая акция» в `ЦенообразованиеРасчет.ПолучитьСкидкиКонтрагента` (запрос `ПроверитьАкцию`). Скидка по акции имеет наивысший приоритет среди составляющих итогового процента.

### Перечисления

#### Enum.ПравилаОкругления

**Бизнес-смысл.** Справочник стратегий округления розничной цены: «До рубля», «До 10», «Психологическое 99» (например, 199, 299).

**Назначение в подсистеме.** Реквизит соглашения о ценообразовании; читается в `ЦенообразованиеРасчет.ОкруглитьЦену` как финальный шаг расчёта — обеспечивает единообразный вид цен в коммерческих документах в зависимости от канала продаж.

#### Enum.КатегорииКлиентов

**Бизнес-смысл.** Маркетинговая категория контрагента: `VIP`, `Новый` и др. Хранится в реквизите `Категория` справочника `Контрагенты`.

**Назначение в подсистеме.** Источник шага «Приоритет 3 — категория контрагента» в расчёте скидок: VIP получает +5 %, Новый клиент +2 %. Также используется в `ОбработкаЗаказов` при подготовке параметров скидки для документа реализации.

### Параметры сеанса

#### SessionParameter.КэшЦен

**Бизнес-смысл.** Сеансовый кэш базовых цен типа `FixedMap` с ключом `Номенклатура|ВидЦены|Дата` — снимает повторные обращения к `ЦеныНоменклатуры.СрезПоследних` в пределах одного сеанса.

**Назначение в подсистеме.** Используется в `ЦенообразованиеРасчет.ПолучитьБазовуюЦену` (чтение через `ПолучитьКэшЦен`, наполнение через `ОбновитьКэшЦен`). Критичен для производительности `РассчитатьЦеныДокумента` и массовых сценариев, где одна и та же позиция запрашивается многократно.

## Изменения относительно v1

- В состав подсистемы добавлены два модуля расчёта (`ОбработкаЗаказов`, `ЦенообразованиеРасчет`), реализующие пакетный и расширенный сценарии поверх существующих `РасчётСкидок` / `ЦенообразованиеСервер`.
- Появилась интерактивная обработка `МассовоеИзменениеЦен` — ранее массовых средств администрирования цен в составе подсистемы не было.
- Подсистема теперь владеет собственным справочником `Акции` (раньше внешние справочники только читались) и двумя перечислениями (`ПравилаОкругления`, `КатегорииКлиентов`), формализующими параметры расчёта.
- Введён параметр сеанса `КэшЦен` для оптимизации повторных расчётов.
- В список регистров фактически добавляется внешний `ИсторияРасчётаЦен` (запись из `ЦенообразованиеРасчет.ЗаписатьИсториюРасчёта`) — в состав подсистемы он не включён, но является исходящей зависимостью.
