# Повторное code review

## Новые замечания

1. `src/CommonModules/ОбработкаЗаказов/Ext/Module.bsl:76`

   В основном запросе по-прежнему используется `Контрагенты.Договор`. В метаданных `Справочник.Контрагенты` такого реквизита не найдено, есть `Партнер`, а договоры живут отдельно/в аналитиках/документе. Заявленное исправление "договор вынесен в основной запрос" выполнено некорректно: запрос, вероятно, не пройдет выполнение или синтаксический контроль. Это было отмечено в первичном ревью как риск, но фактически не устранено.

2. `src/CommonModules/ОбработкаЗаказов/Ext/Module.bsl:63`

   Есть подозрение на изменение бизнес-логики и модели доступа: основная выборка документов теперь выполняется в привилегированном режиме. Раньше `ОбработатьЗаказы` работала без него, а теперь `ВЫБРАТЬ РАЗРЕШЕННЫЕ` фактически обесценивается, потому что RLS обходится на этапе формирования пачки. В многопользовательской среде это может привести к попытке обработки документов, которые пользователь или внешнее соединение не должен видеть по ограничениям доступа.

3. `src/CommonModules/ОбработкаЗаказов/Ext/Module.bsl:183`

   Запись в журнал "Документ обработан и проведен" выполняется до `ЗафиксироватьТранзакцию()` на строке 190. Если фиксация транзакции завершится ошибкой, в журнале может остаться ложная успешная запись вместе с последующей ошибкой. Успех лучше логировать после успешной фиксации транзакции.

4. `src/CommonModules/ОбработкаЗаказов/Ext/Module.bsl:33`

   Для `ДатаНачала` и `ДатаОкончания` проверяется заполненность, но не тип. Затем сразу идут сравнение и `НачалоДня`/`КонецДня`. При вызове экспортной процедуры из внешнего соединения строка, число или другой тип все еще дадут платформенное исключение не на этапе явной валидации.

## Самопроверка

- Новых запросов в цикле не появилось.
- Транзакция на документ добавлена в правильном месте: до блокировки и записи.
- Порядок обработки стал детерминированным за счет `УПОРЯДОЧИТЬ ПО Реализация.Ссылка`.
- Исправление с привилегированным режимом в основной выборке может менять модель доступа по сравнению с кодом до изменений.
- Использование `Контрагенты.Договор` остается блокирующим риском работоспособности запроса.
