## Находка A-01 — «Бог-модуль»: `УправлениеДоступомСлужебный`

**Где:** `УправлениеДоступомСлужебный` (~45 800 строк, 17 именованных областей)

**Что:** Один модуль совмещает семь принципиально разных обязанностей: ядро RLS-расчёта (`ОбновлениеДоступа`), обработчики событий подписок (`ПроверкаДоступаПриИзменении`), лексический анализатор (`ЛексическийАнализ`), синтаксический разбор шаблонов (`СинтаксическийАнализ`), построение параметров ограничения (`ПараметрыОграниченияДоступа`), логику форм (`ПриСозданииНаСервереФормыРедактированияРазрешенныхЗначений` и ещё 5 методов управления формами), и управление пользователями (`ОбновитьРолиПользователей`, `ВключитьПользователяВГруппуДоступа`).

**Почему это проблема:** Любое изменение затрагивает файл целиком — невозможно изолировать правку. Цена merge-конфликтов в поддержке на БСП катастрофически высока. Логика форм, сконцентрированная в серверном общем модуле, нарушает слоёность и создаёт неявную связь «форма → внутренности подсистемы».

**Уверенность:** высокая

## Находка A-02 — Нарушение слоёности: формы напрямую вызывают `УправлениеДоступомСлужебный`

**Где:**
- `Справочник.ГруппыДоступа.ФормаЭлемента` → `УправлениеДоступомСлужебный.ПриСозданииНаСервере*`, `.ПослеЗаписиНаСервере*`, `.ЭтоПрофильОткрытиеВнешнихОтчетовИОбработок`, `.ПроверитьНаличиеПользователяИБВГруппеДоступаАдминистраторы`
- `Справочник.ПрофилиГруппДоступа.ФормаЭлемента` → `УправлениеДоступомСлужебный.ПриСозданииНаСервере*`, `.ПередЗаписьюНаСервере*`, `.ПослеЗаписиНаСервере*`, `.ОбновитьОтображениеНеиспользуемыхВидовДоступа`

**Что:** Формы объектов настройки доступа напрямую вызывают методы внутреннего служебного модуля, минуя публичный API (`УправлениеДоступом`) и промежуточный клиент-серверный модуль.

**Почему это проблема:** Служебный модуль — внутренняя деталь реализации подсистемы БСП. При обновлении БСП сигнатуры этих методов могут измениться без предупреждения. Прямая зависимость формы от кишков подсистемы означает, что любой рефакторинг служебного слоя немедленно ломает UI. Граница «внутри/снаружи» подсистемы стёрта.

**Уверенность:** высокая

## Находка A-03 — Прямые запросы в модулях форм (логика выборки в интерфейсном слое)

**Где:**
- `Справочник.ГруппыДоступа.ФормаЭлемента`, процедуры `ПроверитьПользователейГруппы` (строка ~323), `ОбновитьСоставВидовДоступа` (строка ~1291), `ВосстановитьОбъектБезУчастниковГруппы` (строка ~1665)
- `Справочник.ГруппыДоступа.ВыборПоОтветственному`, `ПриСозданииНаСервере` (строка ~14) — запрос ~80 строк с иерархическим обходом
- `Справочник.ПрофилиГруппДоступа.ФормаЭлемента` — 1 запрос (менее критично)

**Что:** Запросы к данным (`Справочник.ПрофилиГруппДоступа.ВидыДоступа`, `РегистрСведений.СоставыГруппПользователей`, `Справочник.ВнешниеПользователи`) выполняются непосредственно в серверных процедурах модулей форм, а не делегируются менеджер-модулю или служебному модулю.

**Почему это проблема:** Логика отбора дублируется между формой и бизнес-слоем — при изменении модели данных нужно синхронно менять несколько мест. Форма знает о внутренней структуре данных справочников. При появлении новых видов авторизации (например, новый тип внешнего пользователя) нужно не забыть обновить запрос в форме.

**Уверенность:** высокая

## Находка A-04 — Дубль: `ОбновитьРолиПользователей` в публичном API и в служебном модуле

**Где:**
- `УправлениеДоступом.ОбновитьРолиПользователей(МассивПользователей, ПарольСервиса)` — строка 2139
- `УправлениеДоступомСлужебный.ОбновитьРолиПользователей(ОписаниеПользователей, ПарольСервиса, ЕстьИзменения)` — строка 504

**Что:** Два публичных (Экспорт) одноимённых метода с разными сигнатурами — публичный является тонкой обёрткой, но оба доступны извне и оба названы одинаково. Параметр `ЕстьИзменения` (выходной, по ссылке) в служебном методе недоступен через публичный, что вынуждает часть вызывающего кода обращаться напрямую к служебному слою.

**Почему это проблема:** Наличие двух экспортных одноимённых методов размывает ответственность: непонятно, какой вызывать. Обходной вызов служебного метода ради `ЕстьИзменения` закрепляет зависимость на внутренний слой. При следующем обновлении БСП риск рассинхронизации сигнатур высок.

**Уверенность:** высокая

## Находка A-05 — Размытая ответственность: `УправлениеДоступомСлужебный` содержит логику управления формами

**Где:** `УправлениеДоступомСлужебный`, методы:
- `ПриСозданииНаСервереФормыРедактированияРазрешенныхЗначений`
- `ПриПовторномЧтенииНаСервереФормыРедактированияРазрешенныхЗначений`
- `ПередЗаписьюНаСервереФормыРедактированияРазрешенныхЗначений`
- `ПослеЗаписиНаСервереФормыРедактированияРазрешенныхЗначений`
- `ОбновитьОтображениеНеиспользуемыхВидовДоступа`

**Что:** Служебный модуль хранит серверную логику жизненного цикла форм вместе с логикой расчёта прав, обновления ключей и парсинга RLS-шаблонов. По назначению это должно быть в `УправлениеДоступомСлужебныйКлиентСервер` (там уже есть `НазначениеПрофиля`, `ЗаполнитьВсеРазрешеныПредставление`).

**Почему это проблема:** Слой форм и слой данных перемешаны в одном файле. Это дублирует намерение, уже заложенное в архитектуре подсистемы (`КлиентСервер`-модуль существует именно для общей логики форм). Любое изменение UI-поведения требует правки «ядра» подсистемы.

**Уверенность:** высокая

## Находка A-06 — Неявная зависимость через `ПараметрыСеанса` в публичном API

**Где:** `УправлениеДоступом.ЕстьРоль`, строка 168:
```
Запрос.УстановитьПараметр("ТипыВладельцевНастроекПрав", ПараметрыСеанса.ТипыВладельцевНастроекПрав);
```
`УправлениеДоступом.ОтключитьОбновлениеКлючейДоступа` читает и пишет `ПараметрыСеанса.ОтключениеОбновленияКлючейДоступа` (строки 2262, 2323).

**Что:** Публичный API модуля обращается к параметрам сеанса напрямую, не через `УправлениеДоступомСлужебныйПовтИсп`. Параметры сеанса выступают скрытым состоянием, от которого зависит поведение публичных функций.

**Почему это проблема:** Вызывающий код не может предсказать поведение `ЕстьРоль` без знания текущего состояния параметра сеанса `ТипыВладельцевНастроекПрав`. Запись в параметр сеанса из публичного метода (`ОтключитьОбновлениеКлючейДоступа`) означает, что побочный эффект не виден из сигнатуры — скрытая мутация глобального состояния. При расширениях или параллельных фоновых заданиях это источник неожиданных взаимодействий.

**Уверенность:** средняя (точные последствия зависят от специфики сценариев использования — требует проверки на реальных сценариях)

## Находка A-07 — Дубль логики определения «упрощённого интерфейса»

**Где:**
- `УправлениеДоступомСлужебный.УпрощенныйИнтерфейсНастройкиПравДоступа()` — строка 82 (Экспорт)
- `УправлениеДоступом` вызывает `УправлениеДоступомСлужебный.УпрощенныйИнтерфейсНастройкиПравДоступа()` (строка 3122)
- `УправлениеДоступомУТ` имеет собственную проверку `УпрощенныйИнтерфейс`
- `УправлениеДоступомСлужебныйКлиент` — тоже проверяет режим через параметры клиента

**Что:** Признак «упрощённый интерфейс» проверяется в четырёх разных модулях. Служебный метод помечен `Экспорт`, публичный API ничего не экспортирует с таким именем — вызывающий прикладной код вынужден вызывать служебный слой напрямую.

**Почему это проблема:** Точка принятия решения «упрощённый или нет» размыта. Если семантика флага изменится (например, добавится третий режим), правки нужны во всех четырёх местах. Прикладной код, вызывающий `УправлениеДоступомСлужебный.УпрощенныйИнтерфейс*` напрямую, зависит от внутреннего слоя.

**Уверенность:** средняя

## Находка A-08 — `УправлениеДоступомСлужебныйВызовСервера` как пустая обёртка

**Где:** `УправлениеДоступомСлужебныйВызовСервера` — 2 экспортных метода:
- `СформироватьДанныеВыбораПользователя` → проксирует в `Пользователи.СформироватьДанныеВыбораПользователя`
- `ПараметрыРасшифровкиОтчетаАнализПравДоступа` → проксирует в `Отчеты.АнализПравДоступа.ПараметрыРасшифровки`

**Что:** Модуль содержит два метода, ни один из которых не относится к логике управления доступом — один делегирует в подсистему «Пользователи», второй — в отчёт. Оба — чистые прокси без добавленной ценности.

**Почему это проблема:** Модуль создаёт ложное впечатление слоя, тогда как является шумом. Добавление сюда следующего «удобного» прокси укрепляет антипаттерн. Зависимость от `Отчеты.АнализПравДоступа` из Вызов-сервера — неожиданная для слоя «серверные вызовы».

**Уверенность:** средняя
