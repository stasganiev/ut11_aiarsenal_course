# Карта подсистемы «Управление доступом»

> Дата: 2026-05-14 · Платформа: 8.3.27 · База: УТ 11.5 на БСП 3.1.10  
> Цель: навигация для последующих проходов (архитектура / ошибки / производительность)

## 1. Перечень модулей и объектов

### Общие модули

| Объект | Назначение | Слой |
|--------|-----------|------|
| `УправлениеДоступом` | Публичный API подсистемы: проверка прав, работа с наборами значений доступа, управление профилями и группами | Бизнес-логика |
| `УправлениеДоступомПереопределяемый` | Точка кастомизации: объявление видов доступа, профилей, зависимостей прав — конфигурация переопределяет методы этого модуля | Служебный |
| `УправлениеДоступомСлужебный` | Ядро подсистемы (~45 000 строк): расчёт прав, обновление ключей доступа, лексический/синтаксический анализ ограничений, обработчики событий и заданий | Бизнес-логика / Доступ к данным |
| `УправлениеДоступомСлужебныйВызовСервера` | Тонкая обёртка для клиент-серверных вызовов (2 экспортных метода) | Служебный |
| `УправлениеДоступомСлужебныйПовтИсп` | Кэш сеанса: метаданные видов доступа, типы ссылок, параметры ограничений — всё с повторным использованием | Служебный |
| `УправлениеДоступомСлужебныйКлиент` | UI-обработчики на клиенте: таблицы «Виды доступа» и «Значения доступа» в формах, расшифровка отчётов | Интерфейс |
| `УправлениеДоступомСлужебныйКлиентСервер` | Общая логика форм (клиент+сервер): представления, фильтры, параметры форм редактирования | Интерфейс |

### Справочники

| Объект | Назначение | Слой |
|--------|-----------|------|
| `ГруппыДоступа` | Хранит группы доступа; ObjectModule управляет составом пользователей и синхронизирует роли при записи | Бизнес-логика / Доступ к данным |
| `ПрофилиГруппДоступа` | Профили (наборы ролей + виды доступа); при записи транслируют изменения в зависимые группы | Бизнес-логика / Доступ к данным |
| `НаборыГруппДоступа` | Множественные группы для одного пользователя | Доступ к данным |
| `КлючиДоступа` | Справочник ключей доступа (нет ObjectModule — записывается программно) | Доступ к данным |

## 2. Экспортный API подсистемы

Модуль `УправлениеДоступом` — единственная **публичная граница** подсистемы.

### Основные точки входа извне (вызываются из других объектов конфигурации)

| Функция / Процедура | Назначение |
|--------------------|-----------|
| ⭐ `ЕстьРоль(ИмяРоли, ЗначениеДоступа, Пользователь)` | Проверка роли с учётом значений доступа — самый частый вызов |
| ⭐ `ЧтениеРазрешено(ОбъектИлиСсылка)` / `ПроверитьЧтениеРазрешено()` | Проверка права чтения записи |
| ⭐ `ИзменениеРазрешено(ОбъектИлиСсылка)` / `ПроверитьИзменениеРазрешено()` | Проверка права записи |
| ⭐ `ОграничиватьДоступНаУровнеЗаписей()` | Флаг — включён ли RLS (используется в условиях везде) |
| ⭐ `НастроитьОтборыДинамическогоСписка(СписокФорм, ...)` | Накладывает RLS-фильтры на динамический список |
| ⭐ `РазрешенныеЗначенияДляДинамическогоСписка(...)` | Возвращает допустимые значения для отбора в списке |
| `ЕстьПраво(Право, ИмяТаблицы)` | Проверка права на таблицу метаданных |
| `ЗаполнитьНаборыЗначенийДоступа(НаборыЗначений, Объект)` | Заполнение наборов при записи объекта — вызывается из ObjectModule |
| `ОбновитьНаборыЗначенийДоступа(Объект)` | Принудительное обновление наборов |
| `ОбновитьРолиПользователей(Пользователи)` | Синхронизация ролей ИБ-пользователей по группам доступа |
| `ВключитьПрофильПользователю()` / `ВыключитьПрофильПользователю()` | Управление участием пользователя в профиле |
| `ПроизводительныйВариант()` | Определяет режим работы RLS (ключи vs. наборы значений) |
| `НовоеОписаниеПрофиляГруппДоступа()` | Конструктор структуры профиля — используется в `Переопределяемый` |
| `ЗаменитьРолиВПрофилях(ТаблицаЗамен)` | Миграция ролей при обновлении конфигурации |
| `ОтключитьОбновлениеКлючейДоступа()` | Временное отключение фоновых обновлений (для пакетной записи) |
| `ЗаполнениеДанныхДляОграниченияДоступа()` | Запуск полного перезаполнения — вызов из РЗ |
| `РазобранноеОграничение()` / `СтруктураОграничения()` | Парсинг текста шаблона РЛС в структуру |

### API раздела «Для вызова из других подсистем»

| Функция / Процедура | Назначение |
|--------------------|-----------|
| `ПриЧтенииНаСервере(Форма, ТекущийОбъект)` | Хук жизненного цикла формы — вызывается из форм владельцев настроек прав |
| `ПослеЗаписиНаСервере(Форма, ТекущийОбъект)` | Хук жизненного цикла формы |
| `ПараметрыПриСозданииФормыЗначенияДоступа()` | Параметры для формы выбора значения доступа |
| `ПраваПоИдентификаторам(Идентификаторы)` | Получить объекты прав по GUID-идентификаторам |

## 3. Зависимости

### Подсистема зависит от:

| Зависимость | Характер зависимости |
|-------------|---------------------|
| **Пользователи** (БСП) | Управление ИБ-пользователями, группами, выбор пользователей — ~500 обращений |
| **ОбщегоНазначения** (БСП) | Утилиты: типы, значения, транзакции — ~200 обращений |
| **ОбновлениеИнформационнойБазы** (БСП) | Хук `ОбновитьДоступПослеОбновленияИнформационнойБазы` |
| **РегламентныеЗадания** (БСП) | Управление фоновыми заданиями |
| **ЖурналРегистрации** (БСП) | Регистрация изменений прав и ошибок |
| **СтроковыеФункцииКлиентСервер** (БСП) | Вспомогательные строковые операции |
| **Метаданные** платформы | Анализ состава конфигурации (таблицы, поля, типы, роли) |
| `УправлениеДоступомПереопределяемый` | Инжекция бизнес-правил из прикладной конфигурации |
| `УправлениеДоступомУТ` (прикладной) | УТ-специфичные виды доступа (Организации, Партнёры и пр.) |

### От подсистемы зависят:

| Потребитель | Что использует |
|-------------|---------------|
| Все **документы и справочники** с RLS | Подписки на события → проверка / заполнение наборов при записи |
| Все **динамические списки** с ограничением | `НастроитьОтборыДинамическогоСписка`, `РазрешенныеЗначенияДляДинамическогоСписка` |
| **ГруппыДоступа** (ObjectModule) | `ОбновитьРолиПользователей`, `ВключитьПрофильПользователю` |
| **ПрофилиГруппДоступа** (ObjectModule) | `НовоеОписаниеПрофиляГруппДоступа`, обновление зависимых групп |
| **Пользователи** (БСП) | `ОбновитьРолиПользователей` при изменении состава групп |
| **НачальноеЗаполнениеИБ** | `ЗаполнениеДанныхДляОграниченияДоступа` при первом запуске |
| Административные **отчёты** | `ПараметрыДляОтчетов`, `РезультатПроверкиОграниченияДоступа` |

## 4. Точки входа

| Сценарий | Точка входа | Путь управления |
|----------|------------|----------------|
| **Запись любого объекта с RLS** | Подписки `ПроверитьДоступПередЗаписью` / `ПроверитьДоступПриЗаписи` | → `УправлениеДоступомСлужебный.ПроверитьДоступПередЗаписью/ПриЗаписи` |
| **Запись значения доступа** (Контрагент, Организация и т.д.) | Подписки `ОбновитьГруппыЗначенийДоступа*` | → `УправлениеДоступомСлужебный` → обновление `ГруппыЗначенийДоступа` |
| **Открытие динамического списка** | `НастроитьОтборыДинамическогоСписка()` из формы списка | → `УправлениеДоступомСлужебный` → параметры сеанса → отборы СКД |
| **Запись группы/профиля доступа** | ObjectModule `ПриЗаписи` → `ОбновитьРолиПользователей()` | → `УправлениеДоступомСлужебный` → обновление ролей ИБ-пользователей |
| **Фоновое обновление RLS** | РЗ `ОбновлениеДоступаНаУровнеЗаписей` (каждые 15 сек) | → `УправлениеДоступомСлужебный.ОбновлениеДоступаНаУровнеЗаписей` → очередь `ОбновлениеКлючейДоступаКДанным` |
| **Первичное заполнение / обновление ИБ** | РЗ `ЗаполнениеДанныхДляОграниченияДоступа` (каждые 5 мин) или прямой вызов `УправлениеДоступом.ЗаполнениеДанныхДляОграниченияДоступа()` | → `УправлениеДоступомСлужебный.ЗаполнениеДанныхДляОграниченияДоступа*` |
| **Включение RLS администратором** | Запись константы `ОграничиватьДоступНаУровнеЗаписей = Истина` | → `ОбновлениеДоступаНаУровнеЗаписей` в след. цикл |
| **Открытие формы администрирования прав** | `ОбщаяКоманда.ПраваДоступа` / `НастроитьПрава` | → `УправлениеДоступомСлужебныйКлиент` → форма `НастройкиПравОбъектов` |

## 5. Зоны внимания для аудита

> Ниже — **гипотезы** для детальных проходов, не выводы.

### Z-1. «Бог-модуль» `УправлениеДоступомСлужебный` (~45 000 строк)
**Гипотеза:** модуль концентрирует всю логику — RLS-парсер, обработчики событий, фоновые задания, обновление ключей. При любом изменении в подсистеме риск непреднамеренных побочных эффектов высок. Предположительно есть скрытые циклические вызовы между обработчиками событий (запись объекта → обновление групп → запись регистра → снова подписка).  
**Проверить:** цепочки вызовов при записи объектов DefinedType, наличие защиты от повторного входа.

### Z-2. Регламентное задание с интервалом 15 секунд и самоотключением
**Гипотеза:** РЗ `ОбновлениеДоступаНаУровнеЗаписей` с репериодом 15 сек запускается, обрабатывает очередь и затем отключает себя. При высокой нагрузке (массовые операции) очередь `ОбновлениеКлючейДоступаКДанным` может накапливаться быстрее, чем задание успевает её разобрать. Механизм самоотключения может приводить к «застреванию» — если задание завершится с ошибкой, повторный запуск не произойдёт.  
**Проверить:** логику самоотключения, обработку ошибок в хэндлере, поведение при сбое в середине обработки.

### Z-3. Лексический и синтаксический парсер шаблонов RLS (~5 000 строк)
**Гипотеза:** внутри `УправлениеДоступомСлужебный` реализован собственный парсер текстов ограничений (области `ЛексическийАнализ`, `СинтаксическийАнализ`, `АнализИменТаблицИПолейТаблиц`). Такой код сложен в тестировании. Ошибка в парсере может молча формировать некорректный RLS-запрос, который платформа применит без диагностики.  
**Проверить:** покрытие крайних случаев (пустые параметры, нестандартные типы полей), поведение при некорректном шаблоне.

### Z-4. Параметры сеанса как основной транспорт прав (19 параметров)
**Гипотеза:** подсистема активно использует параметры сеанса для передачи прав в RLS-шаблоны платформы. Параметры сеанса устанавливаются при старте сеанса и обновляются через `ОбновитьПараметрыОграниченияДоступа`. Если параметры не обновились (например, после изменения группы доступа без переоткрытия сеанса), пользователь получит устаревшие права до следующей переустановки.  
**Проверить:** как и когда принудительно обновляются параметры сеанса, есть ли риск «застревания» в кэше `ПовтИсп`.

### Z-5. Переопределяемый модуль как точка ручного расширения
**Гипотеза:** `УправлениеДоступомПереопределяемый` вызывает прикладные модули (`УправлениеДоступомУТ`, `УправлениеДоступомЛокализация`, `ТМЦВЭксплуатацииСервер` и др.). Эти модули заполняют виды доступа, профили, зависимости прав. Ошибка или неполное заполнение в одном из них приведёт к тому, что часть объектов конфигурации выпадет из RLS без явного сообщения.  
**Проверить:** полноту регистрации объектов в `ПриЗаполненииСписковСОграничениемДоступа`, соответствие DefinedType-типов и реальных объектов конфигурации.
