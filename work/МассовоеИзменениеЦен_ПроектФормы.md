# Проект формы обработки «Массовое изменение цен»

**Конфигурация:** УТ 11.5 (на поддержке с возможностью изменения)
**Платформа:** 1С:Предприятие 8.3.27, управляемые формы
**Тип объекта:** Обработка `Обработки.МассовоеИзменениеЦен` (новая, добавляется в [src/DataProcessors/](../src/DataProcessors/))
**Имя формы:** `Форма` (основная форма обработки)
**Целевая аудитория:** менеджеры по закупкам
**Источник правды о метаданных:** выгрузка конфигурации в `src/`

---

## 0. Объекты целевой конфигурации, на которые опирается форма

Все имена ниже сверены с XML-выгрузкой в каталоге `src/`.

### 0.1. Документ [`Документы.УстановкаЦенНоменклатуры`](../src/Documents/УстановкаЦенНоменклатуры.xml)

- **Реквизиты шапки (фактические):** `Ответственный` (`СправочникСсылка.Пользователи`), `Комментарий` (`Строка`), `Согласован` (`Булево`), `ДокументОснование` (составной — список документов-оснований), `Статус` (`ПеречислениеСсылка.СтатусыУстановокЦенНоменклатуры`, **проверка заполнения = ВыдаватьОшибку**, значение по умолчанию — `НеСогласован`), `МаркетинговоеМероприятие` (`СправочникСсылка.МаркетинговыеМероприятия`).
- **Табличные части (фактические):**
  - `Товары` — устаревшая ТЧ старого варианта (не используем);
  - **`Товары2_5`** — актуальная ТЧ для нового варианта ценообразования (УТ 11.5). Колонки: `Номенклатура` (`СправочникСсылка.Номенклатура`), `ХарактеристикаЦО` (`СправочникСсылка.ХарактеристикиНоменклатурыДляЦенообразования`), `СерияЦО` (`СправочникСсылка.СерииНоменклатурыДляЦенообразования`), `УпаковкаЦО` (`СправочникСсылка.УпаковкиЕдиницыИзмерения`), `Упаковка` (`СправочникСсылка.УпаковкиЕдиницыИзмерения`), `ВидЦены` (`СправочникСсылка.ВидыЦен`), `Цена` (тип через `ОпределяемыйТип.ДенежнаяСуммаЛюбогоЗнака`), **`ЦенаИзмененаВручную`** (`Булево`), `Формула` (`Строка`), `Валюта` (`СправочникСсылка.Валюты`);
  - `ВидыЦен` — шапочный список видов цен, используемых в документе (нужно заполнить хотя бы одной строкой = выбранный пользователем `ВидЦены`);
  - `НаборыЗначенийДоступа`, `ДополнительныеРеквизиты` — служебные, заполняются штатной логикой/механизмами БСП.
- **Регистры, по которым проводится документ (`RegisterRecords`):** [`РегистрыСведений.ЦеныНоменклатуры25`](../src/InformationRegisters/ЦеныНоменклатуры25.xml) и [`РегистрыСведений.ЦеныНоменклатуры`](../src/InformationRegisters/ЦеныНоменклатуры.xml). При корректно заполненной ТЧ `Товары2_5` оба регистра обновляются штатным модулем проведения документа — **наша обработка САМА в регистры не пишет**.
- **Свойства проведения:** `Posting=Allow`, `RealTimePosting=Deny` → проводим только неоперативно (`РежимПроведенияДокумента.Неоперативный`).
- **Привилегированный режим:** `PostInPrivilegedMode=true`. Дополнительных «обходов» прав со стороны обработки не требуется — документ сам корректно проводится в нужных регистрах при наличии у пользователя права записи документа.

### 0.2. Регистр сведений [`РегистрыСведений.ЦеныНоменклатуры`](../src/InformationRegisters/ЦеныНоменклатуры.xml)

- **Периодичность:** `Секунда`. **Режим записи:** `Подчинение регистратору`. **`EnableTotalsSliceLast=true`** → виртуальная таблица `СрезПоследних` доступна и оптимизирована.
- **Измерения:** `Номенклатура` (`СправочникСсылка.Номенклатура`), `Характеристика` (`СправочникСсылка.ХарактеристикиНоменклатуры` — обратите внимание: это **не** `ХарактеристикиНоменклатурыДляЦенообразования` из ТЧ документа), `ВидЦены` (`СправочникСсылка.ВидыЦен`).
- **Ресурсы:** `Цена` (`ОпределяемыйТип.Цена`), `Упаковка`, `Валюта`.
- **Реквизиты:** `Формула`, `МаркетинговоеМероприятие`.
- Используем только для **чтения текущих цен** (срез последних). Запись — только через документ.

### 0.3. Справочники

- [`Справочники.ВидыЦен`](../src/Catalogs/ВидыЦен.xml) — выбор пользователя.
- [`Справочники.Номенклатура`](../src/Catalogs/Номенклатура.xml) — иерархический справочник.
- [`Справочники.ХарактеристикиНоменклатуры`](../src/Catalogs/ХарактеристикиНоменклатуры.xml) — для отображения характеристик в таблице формы и сопоставления со срезом цен.
- [`Справочники.ХарактеристикиНоменклатурыДляЦенообразования`](../src/Catalogs/ХарактеристикиНоменклатурыДляЦенообразования.xml) — для заполнения ТЧ `Товары2_5` документа.

## 2. Команды формы

| Имя команды | Заголовок (для пользователя) | Что делает |
|---|---|---|
| `Заполнить` | «Заполнить» | Считывает номенклатуру из выбранной группы и заполняет таблицу текущими ценами |
| `Очистить` | «Очистить» | Очищает `ТаблицаНоменклатуры` |
| `ЗаписатьЦены` | «Записать цены» | Создаёт и проводит документ `УстановкаЦенНоменклатуры` по отмеченным строкам |
| `УстановитьВсеПометки` | «Отметить все» | Ставит `Пометка = Истина` для всех строк таблицы |
| `СнятьВсеПометки` | «Снять все пометки» | Ставит `Пометка = Ложь` для всех строк таблицы |

## 3. Описание таблицы номенклатуры (элемент формы)

**Имя элемента формы:** `ТаблицаНоменклатуры`
**Связан с реквизитом:** `ТаблицаНоменклатуры`
**Тип отображения:** Список с возможностью изменения (без иерархии)

### Колонки таблицы (порядок слева направо)

| № | Колонка элемента | Связь с реквизитом-колонкой | Ширина | Только чтение | Оформление / видимость |
|---|---|---|---|---|---|
| 1 | `КолонкаПометка` | `Пометка` | авто (флажок) | Нет | — |
| 2 | `КолонкаНоменклатура` | `Номенклатура` | растяжимая | Да | — |
| 3 | `КолонкаХарактеристика` | `Характеристика` | по содержимому | Да | видимость по функциональной опции `ИспользоватьХарактеристикиНоменклатуры` |
| 4 | `КолонкаУпаковка` | `Упаковка` | по содержимому | Да | видимость по `ИспользоватьУпаковкиНоменклатуры` |
| 5 | `КолонкаТекущаяЦена` | `ТекущаяЦена` | 12 | Да | формат `ЧЦ=15; ЧДЦ=2` |
| 6 | `КолонкаВалюта` | `Валюта` | 6 | Да | — |
| 7 | `КолонкаНоваяЦена` | `НоваяЦена` | 12 | **Нет** (можно править вручную) | формат `ЧЦ=15; ЧДЦ=2`; жёлтый фон, если `Изменилась = Истина`; красный текст, если `НоваяЦена <= 0` |

> Колонки `ХарактеристикаЦО` и `ЦенаИзмененаВручную` в реквизите-таблице есть, но как элементы формы **не выводятся** — это служебные данные для формирования документа.

## 4. Рекомендации по расположению элементов

```
Форма (Группа верхнего уровня — Вертикальная)
│
├── ГруппаПараметрыОтбора (Группа — Обычная, ОтображениеШапка = "Параметры отбора")
│   ├── ГруппаПараметрыСтрока1 (Группа — Горизонтальная)
│   │   ├── ВидЦены                     [ширина ~40]
│   │   └── ДатаУстановки               [ширина ~15]
│   │
│   └── ГруппаПараметрыСтрока2 (Группа — Горизонтальная)
│       ├── ГруппаНоменклатуры          [ширина ~40]
│       ├── ВключаяПодгруппы            [флажок]
│       └── ТолькоСУстановленнойЦеной   [флажок]
│
├── ГруппаКомандыЗаполнения (Группа — КоманднаяПанель)
│   ├── Заполнить                       [основная, ВидКнопки = Действие]
│   └── Очистить
│
├── ГруппаПараметрыПересчёта (Группа — Горизонтальная)
│   ├── ПроцентИзменения                [ширина 10, заголовок "Процент изменения, %"]
│   └── ШагОкругления                   [ширина 10, заголовок "Шаг округления"]
│
├── ТаблицаНоменклатуры                 [растяжимая по высоте и ширине]
│   └── КоманднаяПанельТаблицы
│       ├── УстановитьВсеПометки
│       └── СнятьВсеПометки
│
└── ГруппаКомандыЗаписи (Группа — КоманднаяПанель, выравнивание справа)
    └── ЗаписатьЦены                    [основная, акцентная]
```

### Принципы:
- Сверху вниз — логика работы пользователя: «что меняем» → «где берём» → «как пересчитываем» → «что получилось» → «записать».
- Кнопка **«Заполнить»** — на отдельной командной панели сразу после параметров отбора.
- Поле **«Процент изменения»** — непосредственно над таблицей; изменение значения автоматически пересчитывает колонку `НоваяЦена` без обращения к серверу.
- Кнопка **«Записать цены»** — внизу формы, акцентная, чтобы исключить случайное нажатие до проверки таблицы.
- Группа параметров отбора может сворачиваться (`Свёрнута = Истина`) после первого заполнения, освобождая место под таблицу.

## 6. План разработки кода модуля формы для разработчика

### Этап 1. Заголовок модуля и подготовка
1. Создать обработку `Обработки.МассовоеИзменениеЦен`, основная форма `Форма`. В составе ролей (опционально) — добавить право «Просмотр» этой обработки целевым ролям менеджеров по закупкам.
2. Завести реквизиты формы по п. 1.1 и колонки реквизита-таблицы по п. 1.2; добавить элементы и команды по пп. 3–4.

### Этап 2. Обработчики событий формы
3. `ПриСозданииНаСервере`:
   - значения по умолчанию;
   - видимость колонок `Характеристика`, `Упаковка` через `ПолучитьФункциональнуюОпцию("ИспользоватьХарактеристикиНоменклатуры")` и `…("ИспользоватьУпаковкиНоменклатуры")`;
   - условное оформление: жёлтая заливка `КолонкаНоваяЦена` при `Изменилась = Истина`; красный текст при `НоваяЦена <= 0`;
   - начальная доступность кнопок «Заполнить» и «Записать цены».
4. `ПередЗакрытием` с предупреждением о несохранённых расчётах.

### Этап 3. Сервисные клиентские процедуры
5. `ПересчитатьНовыеЦеныНаКлиенте()`:
   - цикл по `ТаблицаНоменклатуры`;
   - `НоваяЦена = ТекущаяЦена * (1 + ПроцентИзменения / 100)`;
   - применить округление по `ШагОкругления` (если `> 0` — `Окр(НоваяЦена / ШагОкругления, 0) * ШагОкругления`; иначе `Окр(…, 2)`);
   - при программном пересчёте **не** трогать `ЦенаИзмененаВручную` (он управляется только ручным вводом в колонке `НоваяЦена`);
   - выставить `Изменилась = (НоваяЦена <> ТекущаяЦена)`.
6. `Очистить()`, `УстановитьВсеПометки()`, `СнятьВсеПометки()` — простые клиентские процедуры.
7. Все `ПриИзменении` реквизитов отбора (см. п. 5.2) — чистят таблицу. `ВидЦеныПриИзменении` дополнительно вызывает серверную функцию для получения `ВалютаЦены` выбранного вида цен.

### Этап 4. Заполнение таблицы (серверная часть)
8. Клиентская команда `Заполнить(Команда)`:
   - проверка: `ЗначениеЗаполнено(ВидЦены)`, иначе `ПоказатьПредупреждение`;
   - вызов `ЗаполнитьНаСервере()`;
   - после возврата вызвать `ПересчитатьНовыеЦеныНаКлиенте()` (если `ПроцентИзменения <> 0` уже введён).
9. Серверная процедура `ЗаполнитьНаСервере()` — один запрос:
   - таблица `Справочник.Номенклатура` с условием `Родитель В ИЕРАРХИИ (&ГруппаНоменклатуры)` (если `ВключаяПодгруппы = Истина`) или `Родитель = &ГруппаНоменклатуры` (если `Ложь`); исключить `ЭтоГруппа` и `ПометкаУдаления`;
   - **левое** соединение с `РегистрСведений.ЦеныНоменклатуры.СрезПоследних(&ДатаУстановки, ВидЦены = &ВидЦены)` по `Номенклатура`. Если установлен `ТолькоСУстановленнойЦеной` — **внутреннее** соединение или условие `Цены.Цена ЕСТЬ НЕ NULL`;
   - выбираемые поля: `Номенклатура`, `Характеристика`, `Упаковка`, `Цена` КАК `ТекущаяЦена`, `Валюта`;
   - результат выгрузить в `ТаблицаНоменклатуры`. Заполнить служебные колонки: `Пометка = Истина`, `НоваяЦена = ТекущаяЦена`, `Изменилась = Ложь`, `ЦенаИзмененаВручную = Ложь`. Если `Валюта` пуста (нет цены) — подставить `ВалютаВидаЦены`.
   - `ХарактеристикаЦО` — заполняется отдельным шагом (см. этап 5, шаг 11), либо тут же запросом-сопоставлением из `Справочник.Номенклатура` (поле «характеристика для ценообразования», уточнить по модели данных конкретной сборки УТ 11.5). Простейший рабочий вариант — оставить пустой, штатное проведение документа получит её по правилам ценообразования.

### Этап 5. Запись цен через документ
10. Клиентская команда `ЗаписатьЦены(Команда)`:
    - валидация: `ЗначениеЗаполнено(ВидЦены)`; есть отмеченные строки с `Изменилась = Истина`;
    - подсчитать число обрабатываемых позиций;
    - запросить подтверждение через `ПоказатьВопрос` с текстом «Будет создан и проведён документ установки цен на N позиций. Продолжить?»;
    - в callback вызвать `ЗаписатьЦеныНаСервере()`.
11. Серверная функция `ЗаписатьЦеныНаСервере()` возвращает структуру `{Успех, Ссылка, Сообщение}`:
    - `НачатьТранзакцию()` / `Попытка`:
      - `Документ = Документы.УстановкаЦенНоменклатуры.СоздатьДокумент();`
      - `Документ.Дата = ДатаУстановки;`
      - `Документ.Ответственный = Пользователи.ТекущийПользователь();`
      - `Документ.Статус = Перечисления.СтатусыУстановокЦенНоменклатуры.НеСогласован;` (обязательное поле);
      - заполнить шапочную ТЧ `ВидыЦен`: одна строка с `ВидЦены = ВидЦены`;
      - заполнить ТЧ `Товары2_5`: цикл по строкам `ТаблицаНоменклатуры` с `Пометка И Изменилась`, для каждой добавить строку с полями `Номенклатура`, `ХарактеристикаЦО` (из колонки реквизита-таблицы; если пуста — оставить пустой), `Упаковка` (= `Упаковка` строки), `ВидЦены`, `Цена = НоваяЦена`, `Валюта` (= `Валюта` строки или `ВалютаВидаЦены`), `ЦенаИзмененаВручную = ЦенаИзмененаВручную`;
      - **колонки `СерияЦО`, `УпаковкаЦО`, `Формула`** — оставить пустыми (заполнятся штатной логикой / не требуются для базового сценария);
      - `Документ.Записать(РежимЗаписиДокумента.Проведение, РежимПроведенияДокумента.Неоперативный);` (документ запрещает оперативное проведение);
      - `ЗафиксироватьТранзакцию()`;
      - вернуть `{Успех = Истина, Ссылка = Документ.Ссылка}`.
    - `Исключение`:
      - `ОтменитьТранзакцию()`;
      - `ЗаписьЖурналаРегистрации("МассовоеИзменениеЦен.ЗаписьЦен", УровеньЖурналаРегистрации.Ошибка, , , ОписаниеОшибки());`;
      - вернуть `{Успех = Ложь, Сообщение = КраткоеПредставлениеОшибки(ИнформацияОбОшибке())}`.
12. После возврата на клиента:
    - при `Успех = Истина` — `ПоказатьОповещениеПользователя("Цены установлены", , …)`; включить кнопку «Открыть документ»; при необходимости подсветить, что строки уже записаны (например, выставить `Изменилась = Ложь`);
    - при `Успех = Ложь` — `ПоказатьПредупреждение(, Сообщение)`.

### Этап 6. Качество и UX
13. Управление доступностью команд:
    - `Элементы.Заполнить.Доступность = ЗначениеЗаполнено(ВидЦены);`
    - `Элементы.ЗаписатьЦены.Доступность = (ТаблицаНоменклатуры.Количество() > 0) И (есть строки с Пометка И Изменилась);`
    - пересчитывать доступность в обработчиках `ПриИзменении` и после `Заполнить` / `ЗаписатьЦены`.
14. Длительные операции: при `ТаблицаНоменклатуры.Количество() > ~1000` или при ожидаемо большой группе номенклатуры — обернуть `ЗаполнитьНаСервере` и `ЗаписатьЦеныНаСервере` в фоновое задание через `ДлительныеОперации` (БСП в УТ 11.5 присутствует).
15. Тексты сообщений и заголовки — через `НСтр("ru = '…'")`.

### Этап 7. Тестирование
16. Сценарии:
    - заполнение по группе из 1, 100, 5000 позиций;
    - процент = +10, -10, 0; шаг округления = 0, 0.01, 1, 10;
    - часть позиций без текущей цены при `ТолькоСУстановленнойЦеной = Ложь` (в таблице — `ТекущаяЦена = 0`, `НоваяЦена = 0`);
    - повторное «Заполнить» после изменения отбора (старая таблица должна замещаться);
    - ручная правка `НоваяЦена` → флаг `ЦенаИзмененаВручную` уехал в ТЧ документа;
    - запись при отсутствии прав на документ — корректное сообщение об ошибке без срыва формы;
    - проверка, что после успешной записи в регистре `ЦеныНоменклатуры` появились новые срезы (через стандартную форму списка регистра);
    - проверка, что параллельно обновился регистр `ЦеныНоменклатуры25` (документ проводится по обоим — это штатное поведение);
    - отмена транзакции при ошибке проведения — таблица на форме сохраняется, пользователь может исправить и повторить.
