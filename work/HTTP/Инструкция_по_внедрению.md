# Загрузка курсов валют с сайта ЦБ РФ — инструкция по внедрению

Платформа 1С:Предприятие 8.3.27, УТ 11.5 на поддержке с возможностью изменения, БСП 3.1.10.

---

## 0. Важно прочитать до начала

В УТ 11.5 **уже есть штатный механизм загрузки курсов** — подсистема `РаботаСКурсамиВалют`
(общие модули `РаботаСКурсамиВалют`, `РаботаСКурсамиВалютСлужебный`, обработка
`ЗагрузкаКурсовВалют`, регламентное задание штатной поставки). Он загружает курсы
через сервис Интернет-поддержки пользователей, а не напрямую с cbr.ru.

Описанный ниже механизм — **отдельный, независимый**. Он намеренно назван
`ЗагрузкаКурсовВалютЦБ*`, чтобы не пересекаться со штатными именами, и не изменяет
ни одного объекта на поддержке.

**Следствие: если включить оба механизма одновременно, они будут перезаписывать
одни и те же записи регистра `КурсыВалют`.** Перед вводом в эксплуатацию нужно
выбрать один из вариантов:

| Вариант | Что сделать |
|---|---|
| Используем только новый механизм | Отключить штатное регламентное задание загрузки курсов (Администрирование → Обслуживание → Регламентные и фоновые задания) |
| Используем оба | Развести по расписанию и по составу валют, иначе результат зависит от того, кто отработал последним |
| Новый механизм — только для обучения/демо | Не ставить расписание регламентному заданию, запускать вручную через внешнюю обработку |

## 1. Состав поставки

| Файл в `work/HTTP/` | Куда в конфигурации |
|---|---|
| `ЗагрузкаКурсовВалютЦБКлиентСервер.bsl` | Общий модуль `ЗагрузкаКурсовВалютЦБКлиентСервер` |
| `ЗагрузкаКурсовВалютЦБ.bsl` | Общий модуль `ЗагрузкаКурсовВалютЦБ` |
| `ЗагрузкаКурсовВалютЦБРегламентноеЗадание.bsl` | Общий модуль `ЗагрузкаКурсовВалютЦБРегламентноеЗадание` |
| `ВнешняяОбработка_ПроверкаЗагрузкиКурсов.bsl` | Модуль формы внешней обработки (см. раздел 6) |

Разделение на три модуля не декоративное:

- **КлиентСервер** — преобразование чисел и дат без обращения к БД. Такие функции
  проще всего покрыть тестами и они доступны на клиенте.
- **Сервер (`ЗагрузкаКурсовВалютЦБ`)** — HTTP, разбор XML, запись в регистр.
- **Регламентное задание** — только точка входа. Это требование БСП: в модуле задания
  не должно быть прикладной логики, иначе его нельзя вызвать из другого места.

## 2. Что создать в конфигурации

### 2.1. Общие модули (обязательно)

Ветка **Общие → Общие модули**, для каждого — свои флаги:

**`ЗагрузкаКурсовВалютЦБКлиентСервер`**

| Свойство | Значение |
|---|---|
| Клиент (управляемое приложение) | ✔ Истина |
| Сервер | ✔ Истина |
| Внешнее соединение | ✔ Истина |
| Вызов сервера | ✘ Ложь |
| Глобальный | ✘ Ложь |
| Привилегированный | ✘ Ложь |

**`ЗагрузкаКурсовВалютЦБ`** и **`ЗагрузкаКурсовВалютЦБРегламентноеЗадание`**

| Свойство | Значение |
|---|---|
| Клиент (управляемое приложение) | ✘ Ложь |
| Сервер | ✔ Истина |
| Внешнее соединение | ✔ Истина |
| Вызов сервера | ✘ Ложь |
| Привилегированный | ✘ Ложь |

> **Про «Привилегированный»**: модуль записи намеренно НЕ привилегированный.
> Права проверяются штатно, регламентное задание работает под своим пользователем.
> Если в вашей ролевой модели у пользователя регламентных заданий нет права записи
> в `КурсыВалют` — правильное решение это добавить право в роль, а не включить
> привилегированный режим на весь модуль.

### 2.2. Регламентное задание (обязательно)

Ветка **Общие → Регламентные задания** → добавить.

| Свойство | Значение |
|---|---|
| Имя | `ЗагрузкаКурсовВалютЦБ` |
| Синоним | Загрузка курсов валют ЦБ РФ |
| Имя метода | `ЗагрузкаКурсовВалютЦБРегламентноеЗадание.ЗагрузитьКурсыВалют` |
| Использование | ✘ снять (включать после проверки на рабочей базе) |
| Предопределенное | ✔ Истина |
| Ключ | `ЗагрузкаКурсовВалютЦБ` |
| Количество повторов при аварийном завершении | `0` |
| Интервал повтора при аварийном завершении | `0` |

> Повторы платформы выставлены в 0 намеренно: механизм делает собственные
> повторные попытки внутри одного запуска (раздел 4) и не завершается аварийно.
> Двойной уровень повторов дал бы до 9 обращений к сервису вместо 3.

**Расписание** (задается в пользовательском режиме, а не в конфигураторе):
Администрирование → Обслуживание → Регламентные и фоновые задания →
`Загрузка курсов валют ЦБ РФ` → Расписание.

Рекомендуется: **ежедневно, один раз, в 09:30**. ЦБ РФ публикует курсы на следующий
день около 15:00 МСК; запуск утром берет уже опубликованный курс на текущий день.

### 2.3. Константы (необязательно)

Механизм работает без них — значения по умолчанию зашиты в
`ЗагрузкаКурсовВалютЦБКлиентСервер.ПараметрыПодключенияПоУмолчанию()`.
Константы нужны, только если таймаут и число попыток требуется менять
без обновления конфигурации.

| Имя | Тип | Значение по умолчанию | Назначение |
|---|---|---|---|
| `ТаймаутЗагрузкиКурсовВалют` | Число (3,0), неотрицательное | 30 | Таймаут одной попытки, секунд |
| `КоличествоПопытокЗагрузкиКурсовВалют` | Число (2,0), неотрицательное | 3 | Число попыток, включая первую |

Код читает их через `Метаданные.Константы.Найти(...)` — если константы нет,
подставляется значение по умолчанию, ошибки не будет.

> Секретов и токенов в константах нет и быть не должно: сервис ЦБ РФ работает
> без аутентификации. Если в будущем появится источник с ключом — ключ хранить
> только в **безопасном хранилище** (`ОбщегоНазначения.ЗаписатьДанныеВБезопасноеХранилище`),
> не в константе и тем более не в коде.

### 2.4. Разрешение на доступ к внешнему ресурсу

Если в базе **включен профиль безопасности** (обычно на 1С:Фреш и в некоторых
корпоративных контурах), обращение к `www.cbr.ru` нужно разрешить явно.
На файловой базе и обычной клиент-серверной без профилей безопасности этот шаг
не требуется.

Проверить: Администрирование → Интернет-поддержка и сервисы →
«Использовать профили безопасности».

Если включены — добавить в существующий переопределяемый модуль
`РаботаВБезопасномРежимеПереопределяемый.ПриЗаполненииРазрешенийНаДоступКВнешнимРесурсам`:

```bsl
// Разрешение на загрузку курсов валют с сайта ЦБ РФ.
Разрешения = Новый Массив;
Разрешения.Добавить(
    РаботаВБезопасномРежиме.РазрешениеНаИспользованиеИнтернетРесурса(
        "HTTPS", "www.cbr.ru", 443,
        НСтр("ru = 'Загрузка курсов валют ЦБ РФ.'")));

ЗапросыРазрешений.Добавить(
    РаботаВБезопасномРежиме.ЗапросНаИспользованиеВнешнихРесурсов(Разрешения));
```

После изменения — запустить обновление ИБ, чтобы разрешение зарегистрировалось.

### 2.5. Что НЕ нужно создавать

- **Регистр сведений `КурсыВалют`** — уже есть в УТ 11.5. Код использует его
  реальную структуру, проверенную по `src/InformationRegisters/КурсыВалют.xml`:
  - Периодичность: **в пределах дня**;
  - Режим записи: **независимый**;
  - Измерение: `Валюта` (`СправочникСсылка.Валюты`), ведущее;
  - Ресурсы: `Курс` (определяемый тип `КурсВалюты`), `Кратность` (число 10,0).
- **Справочник `Валюты`** — уже есть. Длина кода 3 символа, что совпадает
  с `CharCode` из ответа ЦБ РФ («USD», «EUR»). Сопоставление идет по коду.

## 3. Настройка данных перед первым запуском

1. Открыть **НСИ и администрирование → Валюты**.
2. Убедиться, что нужные валюты заведены и их **код совпадает с буквенным кодом ЦБ РФ**
   (USD, EUR, CNY, ...). Валюта с кодом, которого нет в ответе сервиса, просто
   не получит курс — ошибки не будет.
3. У валют, курс которых должен загружаться, установить признак
   **«Загружается из интернета»** (реквизит `ЗагружаетсяИзИнтернета`).

По умолчанию механизм записывает курсы **только** для валют с этим признаком —
это защищает от перезаписи курсов валют, которые ведутся вручную или по формуле
(реквизиты `СпособУстановкиКурса`, `ФормулаРасчетаКурса`).

> Поведение переключается параметром `ТолькоЗагружаемыеВалюты`. Ставить его в `Ложь`
> на рабочей базе не рекомендуется: перезапишутся в том числе курсы валют,
> установленные вручную.

## 4. Как механизм ведет себя при сбоях

| Ситуация | Поведение |
|---|---|
| Сервис не отвечает / нет сети | 3 попытки с паузами 5 и 10 с, затем запись в ЖР с уровнем «Ошибка». Задание завершается **штатно** |
| Код ответа 5xx, 429, 408 | Считается временным сбоем — повтор |
| Код ответа 4xx (кроме 408/429) | Повтор не выполняется — сервис отвечает стабильно, ждать бессмысленно |
| Код 200, но тело пустое | Ошибка, разбор не начинается |
| Вернулся HTML вместо XML | Проверяется корневой элемент: если не `ValCurs` — ошибка с указанием, что пришло |
| У одной валюты «битый» курс | Пропускается только эта валюта, остальные записываются. Причина — в ЖР |
| Ошибка записи одной валюты | Пропускается только она, цикл продолжается |
| Не записано ни одной валюты | Считается ошибкой механизма, уровень «Ошибка» в ЖР |

Все записи в журнале регистрации идут под событием
**«Загрузка курсов валют ЦБ РФ»** — по нему удобно настроить отбор и мониторинг.

### Ключевые места разбора

- **Кодировка.** Ответ приходит в `windows-1251`. Тело читается как двоичные данные,
  кодировка определяется из XML-декларации, текст перекодируется в юникод, после чего
  из декларации удаляется атрибут `encoding` — иначе построитель DOM попытается
  применить однобайтовую кодировку к уже перекодированной строке и упадет.
- **Запятая.** `Число("57,0471")` даст неверный результат. Строка нормализуется
  в `ЧислоИзСтрокиВнешнегоФормата`: убираются неразрывные пробелы, запятая меняется
  на точку, состав символов проверяется до преобразования.
- **Номинал (`Nominal`).** Для JPY он равен 100 — курс относится к 100 иенам.
  Игнорирование номинала дало бы ошибку **в 100 раз** без каких-либо внешних признаков
  сбоя. Номинал пишется в ресурс `Кратность`; при его отсутствии или некорректности
  валюта **пропускается**, а не записывается с кратностью 1.
- **Отсутствующие поля.** Обязательные (`CharCode`, `Value`, `Nominal`) — пропуск
  элемента с записью причины. Необязательные (`NumCode`, `Name`) — пустая строка.

## 5. Порядок внедрения

1. Создать три общих модуля, вставить в них содержимое соответствующих `.bsl`-файлов.
2. Создать регламентное задание (использование **выключено**).
3. При необходимости создать константы (п. 2.3) и разрешение (п. 2.4).
4. **Синтаксический контроль** конфигурации: Конфигурация → Проверка конфигурации →
   «Синтаксический контроль» + «Проверка логической целостности».
5. Обновить конфигурацию базы данных.
6. Проверить механизм внешней обработкой (раздел 6) — сначала сценарии 1, 4, 2,
   и только потом 3 (запись в базу).
7. Проверить записи в регистре: НСИ и администрирование → Валюты → Курсы валют.
8. Включить регламентное задание и задать расписание.

## 6. Внешняя обработка для проверки

### 6.1. Создание

1. Конфигуратор → **Файл → Новый → Внешняя обработка**.
2. Имя: `ПроверкаЗагрузкиКурсовВалютЦБ`, синоним: «Проверка загрузки курсов валют ЦБ РФ».

### 6.2. Реквизиты формы

Добавить основную форму (**Формы → Добавить → Форма обработки**), на ней создать реквизиты:

| Имя реквизита | Тип | Примечание |
|---|---|---|
| `ТолькоЗагружаемыеВалюты` | Булево | |
| `ДатаКурса` | Дата, состав — **Дата** | Пусто = дата из ответа сервиса |
| `Протокол` | Строка (неограниченная) | Поле — многострочное, только просмотр |
| `РезультатРазбора` | ТаблицаЗначений | Колонки — ниже |

Колонки реквизита `РезультатРазбора`:

| Колонка | Тип |
|---|---|
| `КодВалюты` | Строка (3) |
| `ЦифровойКод` | Строка (10) |
| `Наименование` | Строка (150) |
| `Курс` | Число (20,10) |
| `Кратность` | Число (10,0) |
| `КурсЗаЕдиницу` | Число (20,10) |

> Колонка `КурсЗаЕдиницу` — главный индикатор проверки. Для JPY значение
> `Курс` = 54.1234 при `Кратность` = 100 должно дать `КурсЗаЕдиницу` ≈ 0.54.
> Если `КурсЗаЕдиницу` совпал с `Курс` для JPY — номинал не учтен.

### 6.3. Элементы формы

Перетащить реквизиты на форму, затем добавить **команды формы** и вывести их кнопками:

| Команда | Действие (обработчик) | Заголовок кнопки |
|---|---|---|
| `ПроверитьДоступностьСервиса` | `ПроверитьДоступностьСервиса` | 1. Проверить доступность |
| `ПроверитьРазборОтвета` | `ПроверитьРазборОтвета` | 2. Разобрать ответ (без записи) |
| `ВыполнитьПолнуюЗагрузку` | `ВыполнитьПолнуюЗагрузку` | 3. Загрузить и записать |
| `ПроверитьРазборНаТестовомXML` | `ПроверитьРазборНаТестовомXML` | 4. Разбор контрольного XML |

Форму удобно разделить: сверху — параметры и кнопки, в середине — таблица
`РезультатРазбора`, снизу — поле `Протокол`.

### 6.4. Модуль формы

Содержимое `ВнешняяОбработка_ПроверкаЗагрузкиКурсов.bsl` вставить **в модуль формы**
(не в модуль объекта).

### 6.5. Сценарий проверки

Проверять в таком порядке:

**Шаг 1 — кнопка «4. Разбор контрольного XML».**
Обращения к сети нет, работает и на закрытом контуре. Ожидаемый результат:

```
Разобрано валют: 2
Пропущено элементов: 3
```

В таблице — `AUD` (Кратность 1, КурсЗаЕдиницу = 57.0471) и `JPY`
(Кратность 100, КурсЗаЕдиницу ≈ 0.541234). Пропущены `XXX` (нет `Nominal`),
`YYY` (нечисловой курс), `ZZZ` (нулевой курс) — причины видны в журнале регистрации.

Этот шаг проверяет самое важное: **запятую, номинал и обработку битых данных**.

**Шаг 2 — кнопка «1. Проверить доступность».**
Ожидается «УСПЕХ. Код состояния: 200». Если ошибка — разбираться с сетью, прокси
или профилем безопасности, дальше идти смысла нет.

**Шаг 3 — кнопка «2. Разобрать ответ (без записи)».**
Реальные данные, запись в базу не выполняется. Проверить, что наименования валют
читаются кириллицей без «кракозябр» — это подтверждает корректную работу
с `windows-1251`.

**Шаг 4 — кнопка «3. Загрузить и записать».**
Запись в регистр. После выполнения открыть НСИ и администрирование → Валюты →
Курсы валют и сверить несколько значений с сайтом ЦБ РФ.

**Шаг 5 — проверка регламентного задания.**
Администрирование → Обслуживание → Регламентные и фоновые задания →
`Загрузка курсов валют ЦБ РФ` → «Выполнить сейчас». Затем — журнал регистрации,
отбор по событию «Загрузка курсов валют ЦБ РФ».

### 6.6. Проверка поведения при недоступности сервиса

Полезно убедиться, что задание не падает. Самый простой способ — временно указать
несуществующий хост: в `ПараметрыПодключенияПоУмолчанию()` заменить `www.cbr.ru`
на `www.cbr.invalid` и нажать «1. Проверить доступность».

Ожидаемое поведение: три попытки с паузами, в протоколе — «ОШИБКА», в журнале
регистрации — три предупреждения и одна итоговая ошибка. **Задание при этом
завершается штатно, а не аварийно.** После проверки вернуть адрес обратно.

| Требование | Где реализовано |

| Таймаут соединения | `ВыполнитьЗапросКСервису`: 7-й параметр `HTTPСоединение`, по умолчанию 30 с |
| Код состояния проверяется до разбора тела | `ВыполнитьЗапросКСервису`: блок `<validation>` до `ПолучитьТелоКакДвоичныеДанные` |
| Недоступность сервиса не рушит задание | `ПолучитьДанныеСервиса` — `Попытка` вокруг каждой попытки; `ЗагрузитьКурсыВалют` — верхнеуровневый перехват |
| Повторные попытки | 3 попытки, паузы 5 и 10 с, только при временных сбоях (`ОшибкаВременная`) |
| Запись в ЖР успеха и каждой ошибки | `ВыполнитьЗагрузку` (успех), плюс запись на каждой неудачной попытке, ошибке разбора и ошибке записи |
| Проверка непустого ответа и структуры до обращения к полям | `РазобратьОтветСервиса`: проверка `Неопределено`, пустого текста, корневого элемента `ValCurs`, наличия `Valute` |
| Явная обработка кодировки | `ТекстОтветаВЮникоде` + `КодировкаИзОбъявленияXML` + `ЗаменитьОбъявлениеКодировки` |
| Числа с запятой | `ЧислоИзСтрокиВнешнегоФормата` |
| Номиналы и множители | `РазобратьЭлементВалюты`: `Nominal` → ресурс `Кратность`, при некорректном значении элемент пропускается |
| Отсутствующие поля | `ЗначениеДочернегоЭлемента` / `ЗначениеАтрибута` возвращают пустую строку вместо исключения |
| Пустые и нулевые значения | Курс ≤ 0 и кратность ≤ 0 отбраковываются |
| Нет пустых блоков `Исключение` | Каждый блок пишет в ЖР либо возвращает результат вызывающему коду |
| Секретов в коде нет | Сервис без аутентификации; `БезопасныйАдресДляЖурнала` скрывает параметры строки запроса на случай смены источника |
| Один запрос на весь пакет | Сервис отдает все курсы одним ответом; HTTP-запроса в цикле по валютам нет |
| Нет запросов к БД в цикле | `ВалютыПоКодам` — один запрос на весь пакет |

## 8. Известные ограничения

1. **Запись идет наборами по одной валюте.** Для ~40 валют ЦБ РФ это приемлемо
   (сотни миллисекунд). Плюс подхода — ошибка по одной валюте не откатывает остальные.
   При переходе на источник с тысячами позиций запись нужно переделать
   на один набор с общим отбором по периоду.

2. **Транзакция на всю загрузку не открывается сознательно.** Иначе ошибка на последней
   валюте откатила бы весь пакет — для курсов это хуже, чем частичная загрузка.

3. **Механизм не заполняет `КурсыВалютРасчетовПоДоговорам` и не пересчитывает
   зависимые валюты** (те, у которых `СпособУстановкиКурса` = «По формуле»).
   Штатно этим занимается `РаботаСКурсамиВалют.СписокЗависимыхВалют`.
   Если в базе есть валюты с формулой — после загрузки их нужно пересчитывать
   отдельно; в текущей версии это не реализовано.

4. **Праздничные и выходные дни.** ЦБ РФ в эти дни отдает курс последнего рабочего
   дня, а атрибут `Date` содержит дату этого рабочего дня. Механизм пишет курс
   на дату из ответа, поэтому за выходные записи не появятся. Если нужен курс
   на каждый календарный день — передавать `ДатаКурса` явно.
